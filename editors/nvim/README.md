# jacket.nvim

> [!NOTE]
> This project is unofficial and is not affiliated with or endorsed by Thekla or the official Jai project.

Neovim support for Jai from [Jacket](https://github.com/matteopolak/jacket): the `jailsp` language server (diagnostics with `jailint` lints and quick fixes, hover, completion, go to definition, semantic tokens, doc-comment links), `jaifmt` formatting, a Vim syntax file, and a command that downloads the toolchain. Needs Neovim 0.11 or newer.

This directory is mirrored to [matteopolak/jacket.nvim](https://github.com/matteopolak/jacket.nvim) on every release. Install from there, or use a checkout of the jacket repository.

## Install

With `vim.pack` (Neovim 0.12+):

```lua
vim.pack.add({ 'https://github.com/matteopolak/jacket.nvim' })
require('jai').setup({}) -- optional
```

With [lazy.nvim](https://github.com/folke/lazy.nvim):

```lua
{
  'matteopolak/jacket.nvim',
  ft = 'jai',
  opts = {}, -- optional; see Settings
}
```

By hand, as a package:

```sh
git clone https://github.com/matteopolak/jacket.nvim ~/.local/share/nvim/site/pack/jai/start/jacket.nvim
```

Or from a checkout of the jacket repository, in `init.lua`:

```lua
vim.opt.rtp:append('/path/to/jai/editors/nvim')
```

The plugin enables the server itself (`vim.lsp.enable('jailsp')`), so nothing else is needed. A checkout of the repository downloads the toolchain of the version in `lua/jai/version.lua`, which can be older than the checkout; set `toolchain.version` or put `jailsp` on `PATH` to use another.

### Only the language server

Without the plugin, a minimal setup is:

```lua
vim.filetype.add({ extension = { jai = 'jai' } })
vim.lsp.config('jailsp', {
  cmd = { 'jailsp' },
  filetypes = { 'jai' },
  root_markers = { 'jai.toml', 'jailint.toml', '.git' },
})
vim.lsp.enable('jailsp')
```

`jailsp` needs `file://` documents and a stdlib: it finds `stdlib/` next to its executable, or from `JAIC_STDLIB` (`cmd_env = { JAIC_STDLIB = '/path/to/stdlib' }`). The plugin does not use nvim-lspconfig, so the two do not conflict; nvim-lspconfig has no `jailsp` config as of writing, so the snippet above is what to use there as well.

## The toolchain

The plugin looks for each tool (`jailsp`, `jaic`, `jaifmt`, `jailint`) in this order and uses the first match:

1. the setting (`server.path`, `compiler.path`, `formatter.path`); a path that does not exist is an error, not a fallback;
2. `PATH`;
3. next to `jaic` (from `compiler.path` or `PATH`);
4. the toolchain downloaded by `:Jai install`, in `stdpath('data')/jai/<version>`.

When no `jailsp` is found, the plugin asks once per session whether to download the toolchain (`toolchain.auto_download = 'prompt'`); `'always'` downloads without asking and `'never'` only prints how to install it. `:Jai install` downloads the release that matches the plugin's version from GitHub with `curl`, checks its SHA-256 (the checksums shipped with the plugin, else the release's `SHA256SUMS`), and unpacks it with `tar`. Older downloaded versions are removed.

## Settings

All optional. Either `require('jai').setup({ ... })` or a `vim.g.jai = { ... }` table set before the plugin loads (`setup()` wins):

| Setting | Default | Meaning |
| --- | --- | --- |
| `server.path` | `''` | Path to `jailsp` |
| `compiler.path` | `''` | Path to `jaic` (for `:Jai run`, `build`, `check`) |
| `formatter.path` | `''` | Path to `jaifmt` |
| `stdlib.path` | `''` | Standard library folder, passed as `JAIC_STDLIB` |
| `toolchain.auto_download` | `'prompt'` | `'prompt'`, `'always'` or `'never'` |
| `toolchain.version` | `''` | Toolchain version to download; empty is the plugin's version |
| `completion.auto_import` | `true` | Complete names the file cannot see yet and add the `#import` |
| `run.arguments` | `{}` | Extra `jaic` arguments, e.g. `{ '-O2' }` |
| `format_on_save` | `false` | Format with `jaifmt` before writing |
| `lsp.enable` | `true` | Call `vim.lsp.enable('jailsp')` when the plugin loads |

`completion.auto_import` reaches the server as its initialization options and `workspace/didChangeConfiguration`, as in the VS Code extension. Change the server's client settings per project with `vim.lsp.config('jailsp', { ... })`; it is merged over `lsp/jailsp.lua`.

## Commands

`:Jai <subcommand>` (tab-completes):

| Subcommand | Does |
| --- | --- |
| `install` / `update` | Download the toolchain and restart the server |
| `restart` | Restart `jailsp` |
| `fix` | Apply `jailint`'s safe fixes to the buffer (`source.fixAll.jailint`) |
| `lint` | Run `jailint` over the project into the quickfix list |
| `format` | Format the buffer with `jaifmt` |
| `expand` | Show the code generated by the `#insert`, `#run` or macro call under the cursor |
| `polymorphs` | List the instances of the polymorphic procedure under the cursor |
| `run`, `build`, `check` | `jaic <file>` (with `-interp` for `run` and `-check` for `check`) in a terminal split |
| `health` | `:checkhealth jai` |

`jailsp` has no `textDocument/formatting`, so `vim.lsp.buf.format()` does nothing for Jai; use `:Jai format` or `format_on_save`. Quick fixes and the rest of the LSP features work through the usual `vim.lsp.buf.*` functions and Neovim's default mappings.

## Highlighting

`syntax/jai.vim` highlights keywords, directives, notes, strings (including `#string END` here-strings), numbers and comments; the server's semantic tokens are drawn over it. For tree-sitter, [constantitus/tree-sitter-jai](https://github.com/constantitus/tree-sitter-jai) is a Jai grammar that was updated recently; this plugin neither bundles it nor has been tested with it.

## `:checkhealth jai`

Reports the Neovim version, which of `jailsp`, `jaic`, `jaifmt` and `jailint` were found (where, and their versions), whether `jailsp` is enabled, and the clients attached.

## Tests

```sh
cd editors/nvim
JAILSP=/path/to/jailsp nvim --headless --clean -u tests/minimal_init.lua -c 'luafile tests/run.lua'
```

Without `JAILSP` the end-to-end spec is skipped. From the repository root, `just nvim-test` builds `jailsp` and runs everything. More in [docs/tools/neovim-plugin.md](../../docs/tools/neovim-plugin.md).

## Publishing the mirror (maintainers)

The `neovim` job of `.github/workflows/release.yml` pushes this directory to `matteopolak/jacket.nvim` and tags it `vX.Y.Z`. It authenticates with an SSH deploy key: add the public key to `jacket.nvim` as a deploy key with write access and the private key to the jai repository as the secret `NVIM_MIRROR_DEPLOY_KEY`. Without the secret the job skips.
