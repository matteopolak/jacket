# C ABI items the stdlib declares by hand, checked against real C headers.
#
# crates/jaic-cli/tests/abi_layout/mod.rs turns the entries for one target into a C program
# (system headers) and a Jai program (stdlib bindings) and compares every value they report.
# The `stdlib_c_abi_matches_host_headers` native test does this on every CI host; other targets
# can be checked without running them (JAIC_ABI_CROSS). See docs/stdlib/native-bindings.md.
#
# Syntax (one item per line, `#` starts a comment line):
#   [linux macos-x64 ...]       the following lines apply to these OSes or os-cpu targets
#   c: <text>                   a line of C before the checks (#define, #include)
#   jai: <text>                 a line of Jai before the checks (#import)
#   struct <Jai> [= <C>] : <field> <jai_field>=<c_field> <flexible>[] ...
#                               size, alignment, and each field's offset and size
#                               (`name[]` is a C flexible array member: offset only)
#   packed struct ...           a C packed struct: as `struct`, without the alignment (Jai
#                               cannot lower a struct's alignment below its members')
#   type <Jai> [= <C>]          size and alignment only (opaque types, unions, arrays)
#   int <Jai> [= <C>]           size and signedness of an integer typedef
#   const <name> <jai>=<c> ...  integer constants; `jai` may be any Jai expression without spaces
# The C name defaults to the Jai name; C struct tags need `= struct <tag>`. Field paths may use
# dots (`uc_mcontext.pc`) and see through `using` and anonymous Jai members.
