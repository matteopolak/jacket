# Compile-time execution

## What it is

`#run` is a source request to execute checked Jai code in the independent Rust VM. Its result becomes typed constant IR; virtual pointers never become native addresses.

## How it works

The syntax layer preserves expression requests, void blocks, and explicitly typed anonymous bodies (`#run -> int { return 42; }`). A prefix request binds a call or primary expression: `#run factorial(5) + 2` runs the call, while `#run (factorial(5) + 2)` runs the whole expression.

A declaration initialized directly by a block-form run may omit its semicolon after the closing brace, as in `ANSWER :: #run -> int { return 42; }`. A run call or a larger expression containing a run still requires the ordinary declaration terminator. See [source forms from recent projects](project-source-forms.md).

Module loading records active file directives together with their defining `FileInstanceId` and `SourceSpan`. Inactive `#if` branches produce no run requests. These identities keep file-private names and diagnostics attached to the original file.

`jai-sema::compile_time` supplies a provider for ready checked procedures against a `TypeView`, without requiring the whole registry to freeze. Its construction validates each available body against known signatures and the current place snapshot. An unavailable source body is a `Procedure` dependency, rather than a successful fabricated constant.

Expressions containing checked temporary bindings execute with their genuine semantic procedure owner. Ordinary and resumable VM entry points validate that owner before running producers or opening an effects transaction. Pure header helpers with no owner use the strict ownerless entry point; they cannot accept a binding merely because a scratch procedure happens to have the same numeric identity.

Explicit `#intrinsic` prototypes bind to a closed runtime catalog. The provider refreshes selected generic and local prototypes after argument binding, preserving their actual procedure identities. Memory and atomic intrinsics run against virtual memory with the selected target layout and byte order; ordinary names and foreign procedures do not acquire intrinsic behavior.

Ordinary execution has three outcomes: `Complete`, `Pending`, and `Failed`. An unflagged pending or failed attempt rolls back virtual memory and staged compiler effects. Completed integers, floats, booleans, strings, fixed arrays, structs, unions, distinct values, and enums are materialized as nominal typed constants. String views are copied into owned bytes while the VM transaction remains open; conversion failure rolls back effects. Values without a corresponding constant IR representation fail explicitly.

`#run,stallable` instead retains the exact VM continuation when a dependency suspends execution. Its typed input, temporary anonymous procedure, frames, memory checkpoint, source origin, and open effect journal stay together. A driver may service the dependency synchronously and resume immediately. Otherwise `PreparedLibrarySession::drive` returns typed `LibraryReadiness::Pending` while retaining the original graph and semantic arenas. A later drive resumes the saved operation; it does not bind or execute the preceding source again. Other requests sharing that virtual state wait for the suspended transaction. Terminal failure or explicit session cancellation retires every parked token through its original effects handler and rolls back its checkpoint.

Stored aggregates preserve initialized bytes and virtual provenance, including inactive union storage. Publication first proves that canonical constant encoding preserves those facts. A snapshot with initialization holes or noncanonical inactive bytes fails before effects commit; the source adapter never silently drops its backing storage.

An annotated constant or contextual value supplies its destination `TypeId` to the run request. Binding checks the source conversion before execution, and the VM validates and materializes the converted destination inside its transaction. Anonymous bodies check their declared result against that destination before binding their statements. A rejected destination therefore cannot commit effects; pending effect responses also roll back normally. The request cache distinguishes destination types as well as source identities.

A source cast directly enclosing `#run` lowers its checked conversion into the same VM expression. Range failures therefore roll back the effectful call that produced the value, rather than rejecting an already committed result.

Lexical constant result groups such as `IS_INTEGER, SIGNED, BITS :: #run facts(T);` bind each name to a projection of one ordered result vector. Pure header selection checks the destination count and each `#must` discard before argument binding. One VM transaction then normalizes the entire vector under a shared publication budget and validates every typed constant before committing effects. All projections reuse the same cached vector; an all-discard group still executes its initializer. The current group initializer must be a direct or qualified procedure call.

Pointer-to-integer casts retain typed address provenance through VM arithmetic and memory copies. Address-derived integers cannot become native constants, including inside aggregates. This check runs before effects commit and does not compare integer bits against address patterns. Proven address-independent results, such as distances within one allocation or alignment residues, can materialize as ordinary integers.

The semantic worklist publishes concrete signatures first, binds available bodies, and retries requests waiting on bodies or deferred constant declarations. Generic specializations join the same queue with their defining file and immutable substitution. A fixed point without progress produces an unresolved or cyclic dependency diagnostic. Named constants containing a run, and other constants referencing them, bypass the restricted scalar evaluator.

Module quotation constants and their aliases join this typed readiness phase but bind directly into the Code registry. Their quoted bodies remain source data, and no runtime constant or VM pointer is fabricated for them.

Instantiated record methods are checked through the same session, including unused methods in libraries without ordinary procedures. New instances created while binding bodies trigger another sweep. Method dependencies join the existing worklist, and method diagnostics retain their defining source file.

Header preparation can drive the retained worklist before global initializer publication. It starts with the exact pending record fields and follows their typed field, procedure, and constant dependencies. Unbound typed and sequence constants also join this queue, so a prerequisite can read an actual array constant before globals exist. Already published values skip repeated evaluation. Only prerequisite method headers and bodies execute in this mode; unrelated bodies, constants, file runs, guards, and alignment jobs wait for the full phase. `HeadersReady` retains all checked bodies and completed run receipts for that phase, and cannot be returned while a VM continuation remains parked.

Global alignment annotations are readiness jobs keyed by their actual global identities and defining source declarations. Checked bodies and deferred constants can supply the request. The VM reports `GlobalAlignment` before allocating or accessing a global whose request remains pending; publication updates the alignment sidecar before a later readiness round permits allocation. Self-dependent requests reach a cycle diagnostic instead of silently allocating at natural alignment.

Auxiliary modifier bodies use the same body queue with their actual rewritten procedure syntax and signature. Their binding uses `NoEffects` and a separate VM cache, including nested source run requests in that body, so binding cannot publish compiler effects or production virtual-global changes. Selected generic and local dependency bodies inherit that isolation during binding. Auxiliary identities remain available to readiness providers, but their bodies, debug records, inline/phase hints, and local alignment metadata are excluded from the final runtime library. Ordinary dependency bodies retain their runtime metadata.

Anonymous blocks are temporary checked procedures. The request cache reserves their real procedure identity once and reuses it when body binding waits on a dependency. Newly declared lexical scopes belong to that temporary owner while captured scopes keep their defining identities. Nested completed requests therefore retain their cache and ownership proofs during a retry. A shared VM state preserves committed virtual globals between requests. Results are cached by defining file, stable procedure owner, canonical source specialization, destination, source span, and immutable lexical capture facts. Active quotation and macro chains distinguish two insertions of the same source directive; current-scope insertion also includes its current bindings. Storage facts use bounded structural projection keys, so retrying a projection does not acquire a new cache identity solely because its allocation ordinal changed. Discovery guards sharing a containing procedure still use distinct specialization keys. Runnable file directives can execute while body diagnostics remain deferred, allowing committed source additions to trigger a driver graph rebuild. Without progress, the original body error is reported. A directive that creates a generic specialization returns to the same worklist before it retries; later directives wait for it to complete.

Providers take an owned snapshot of the real file globals followed by append-only local external definitions. The VM never receives placeholder globals or a reordered identity list. A temporary procedure that owns external data or a foreign library retains a checked compile-time-only owner receipt with its original source allocation and place arena. That ledger proves declaration ownership separately from runtime bodies; it does not create an executable fallback or authorize host access.

Effects handlers receive stable source metadata before execution: workspace, source path, run span, exact source bytes, and canonical specialization bytes. This lets the driver replay a committed request/response stream after added source causes a graph rebuild. The versioned module environment includes bound parameter values, source declaration identities, program-wide facts, and selected target facts. The same recipe in two parameterized module instances has distinct replay bytes even when its text and signature match. Semantic arena IDs are excluded from this identity. A source hash accelerates lookup; exact bytes remain part of equality. Effect finalization can fail, which restores virtual state and reports a source error.

Quoted and expanded requests use the original AST source location. Their stable containing-procedure origin and captured lexical facts distinguish the same quotation expanded by different callers or baked values; transient cache keys also retain the original source identity. The receipt codec uses explicit typed values and structural layouts rather than diagnostic formatting or arena indices. Adding an unused type or callback alias does not change an existing recipe's receipt. Local nominal types, nested procedures, and lambdas include both owner and defining-file module environments in replay bytes. An incomplete environment is an explicit error, so a parameterized module cannot reuse another instance's committed effects.

Dependency discovery can borrow this worklist before the graph is complete. Retained condition requests bind against the available signatures and checked bodies, returning actual boolean decisions or explicit pending diagnostics. A decision ends that preparation pass so discovery can load only its selected branch; it does not require unrelated runtime bodies to finish. The completed graph retains the decision for final body binding.

## How to change it

Extend `crates/jai-syntax/src/compile_time.rs` for new request syntax and keep source spans intact. `modules/compile_time.rs::BindSession` groups the shared semantic arenas, readiness maps, effects bridge, and optional discovery jobs; add phase inputs there instead of extending positional call arguments. Add constant materialization in `crates/jai-sema/src/compile_time.rs` together with the matching checked IR, verifier, VM, and native backend support. Preserve nominal IDs when converting aggregate values.

`compile_time/suspension.rs` owns the continuation cache and validated publication boundary. `modules/compile_time/worklist.rs` retains binding queues and completed recipes between drives. Keep `Worklist::cancel` and the public session lifecycle connected when adding another suspended capability; dropping a token alone cannot cancel a provider's parked host transaction. Source APIs accepting `CompileTimeRun` must preserve its flags. Live computed-using results currently reject the stallable flag explicitly because their slice consumer lacks a retained publication callback.

`compile_time/owners.rs` seals actual temporary procedure receipts when their declarations require one. Construct the shared place snapshot before checking the body, and preserve its allocation when retaining the proof. Reuse a receipt only for the same procedure signature and exact source allocation and span. Global snapshots must preserve the ledger's dense IDs and external metadata across retries and continuation resumes.

`modules/compile_time/header_prerequisites.rs` retains the dependency sets used by `BindingMode::Headers`. Extend these sets from typed pending channels, never diagnostic text. Preserve the worklist when returning `HeadersReady`, and refresh queued concrete signatures after header completion so bodies observe actual parameter defaults.

Keep the restricted `jai-eval` evaluator separate: it rejects `#run` because procedure execution requires the typed VM. `compile_time/provider.rs` owns the sealed ready provider and capability maps. The provider must validate bodies before advertising them as ready. Retrying dependencies must terminate with a source-located diagnostic when no further body can become ready.

Nested procedure and method binders use `Context::for_source` with their own procedure identity and defining file. Merge the child's pending channels back into its parent after binding, including on failure, so imported definitions retain source provenance and participate in the shared readiness worklist.

Keep `EvaluationScope` connected to an authorized expression owner when adding a pure or contextual evaluator. Once that authority exists, its actual `Context::owner` selects the execution domain. An explicit absent expression owner remains ownerless even when a context is retained. Do not infer an owner from the first signature or a scratch resolver. Resumable inputs retain their original checked owner across suspension and publication.

When callback contracts strengthen for an existing generic specialization, its actual procedure identity returns to the body queue. The scheduler removes the old checked body and its debug sidecar, and ready providers consult the current generic readiness state. A typed contract revision counts as progress without allocating another procedure identity. Completed run values retain the revision of their proof. After it changes, cache reuse waits for the actual callback rechecks; failed rechecks remain unavailable. Successful rechecks permit reuse without repeating already committed compiler effects.

The result-vector cache follows the same callback-proof rule and retains the original declaration group's usage mask in its key. Extend `compile_time/results.rs` for additional group initializer forms, preserving pure count/contract preflight and the single publication transaction.

`compile_time/callback_readiness.rs` applies the same proof rule to local source procedures. Its revision stores separate graph and local counters and checks the actual bodies queried by the recipe's provider, including transitive and indirect calls. The read set is bounded by `Limits.value_cells`. Keep that read set and execution-start proof across suspension, and check it before resume and commit. Check retained terminal failures even when the revision is unchanged: an execution can first query an already failed body. Propagate its original source diagnostic and cancel any parked transaction instead of reporting a pending cycle. Waiting for every pending body would make an independent cached seed inside a rechecked body wait for its own enclosing body. Local same-identity invalidation, provider read tracking, and readiness must change together; registering only the cache helper would still leave stale bodies available to the VM. A contract revision in either registry advances the worklist fixed point without allocating a replacement procedure identity.

Compiler-only Code execution is being prepared separately from native procedure IR. The unregistered `procedure_headers/compiler_code.rs` classifier identifies a canonical closed Code result before ordinary parameter defaults or native ABI construction. `compile_time/compiler_plan_binding.rs` stages an explicit binding mode that denies nested source execution before cache lookup; a fresh cache and `NoEffects` alone do not enforce this boundary. `compile_time/compiler_values.rs` stages selected native capture conversion while the plan's single journal remains open. Registration requires the checked Code controller, source capture receipt, final graph validation, and cancellation hooks together. These helpers do not yet enable executable Code producers.

Measure worklist progress using completed source bodies and requests. Generated context-call adapters are inventory artifacts; producing another adapter while retrying a failed body does not advance readiness. `semantic_ready_count` makes that distinction without inspecting diagnostic text.

Use `Diagnostic::at_source` when transporting VM diagnostics through semantic binding. Its explicit source identity prevents a quoted request's error from being reassigned to the caller's file.

## Configuration

`jai_vm::Limits` controls fuel, call stack depth, evaluation depth, allocations, and value cells. `ResolveOptions.compile_time_limits` selects these limits, `target` supplies selected target facts including byte order, `layout` supports an explicit layout-only policy, `compiler` carries compiler intrinsic binding metadata, `file_abi` optionally carries the canonical stdio source receipt, and `process_abi` optionally carries the canonical POSIX process source receipt. Host paths remain bounded by the effects handler's explicit file scope. The options entry points borrow a driver effects handler; compatibility entry points use `NoEffects`. Default execution allows 1,000,000 steps, 128 frames, 256 evaluation levels, 16,384 allocations, and 1,000,000 value cells. Hard stack and depth ceilings also protect the Rust interpreter.

## Dependencies

This flow uses `jai-syntax`, `jai-modules`, `jai-source`, `jai-types`, `jai-ir`, and `jai-vm`. Compiler effects are typed requests handled by the driver. An explicitly configured `ResolveOptions.file_abi` receipt can bind canonical POSIX stdio prototypes to the typed File adapter. Readiness providers verify their exact procedure identities and signatures before exposing `FileAbi`; the same receipt can authorize the exact Default_Allocator C allocator prototypes through `HeapAbi`, and other foreign prototypes remain unavailable to compile-time execution. Heap calls operate on bounded virtual allocations in the VM state and roll back with the run; they never call native malloc. The shared effects bridge forwards host requests and path scopes through the same transaction handler. No original reference executable, object, or library is loaded or executed.

An authenticated `process_abi` receipt supplies a separate checked capability map for virtual POSIX operations. The worklist retains that map across suspension, and providers reject duplicate capabilities or mismatched procedure identities and signatures. Scalar pipe, descriptor, PID, and errno operations use the VM's transactional process state. Fork, exit, and exec control require their own continuation scheduler; the scalar adapter reports them as unsupported until that integration exists.
