# Scalar handle analysis

This domain discovers native acquisition origins returned by checked procedures, with explicit conditions needed to establish continued liveness. It is separate from pointer-allocation provenance: descriptor zero is valid, and equal numeric handles from separate acquisitions do not establish shared identity.

`Analysis::caller_openings` reads the compiler's lifetime sidecar for one lint invocation. It accepts a body only when its map key and recorded procedure agree, checking has completed and its syntax `Arc` still matches the procedure. Native boundaries require a selected foreign target, recognized system library and compatible checked C signature. Windows handle protocols additionally require the selected Windows target; a foreign library spelling cannot override the compilation target. An ordinary function named `fopen` establishes no fact.

The supported native matrix is deliberately narrow:

| Selected target | System libraries | Protocols |
| --- | --- | --- |
| Linux | `c`, `libc` | `open`/`close`, `fopen`/`fclose`, GNU `fcloseall` |
| macOS | `c`, `libc`, `System` | `open`/`close`, `fopen`/`fclose` |
| Windows | `kernel32` (case insensitive) | `CreateFileW`/`CloseHandle` |

These contracts require X64 or Arm64 and actual eight-byte checked pointer parameters/results. Other target/library combinations, including unsupported Windows CRT aliases, are unknown. ISO C portability does not identify the selected linked implementation. The Linux contracts above and Apple's [fopen](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/fopen.3.html), [fclose](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/fclose.3.html) and [close](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/close.2.html) contracts bound this initial platform coverage. In particular, no Linux failure-release policy is applied to macOS `close`.

Fixed native prototypes reject variadic declarations, even when the retained ellipsis metadata resembles an ordinary pointer parameter. The supported variadic `open` form has two fixed arguments followed by 32-bit mode metadata, matching the [Linux](https://man7.org/linux/man-pages/man2/open.2.html) and [Apple](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/open.2.html) contracts. On Apple Arm64, a fixed third argument is not equivalent: [Apple's ABI](https://developer.apple.com/documentation/xcode/writing-arm64-code-for-apple-platforms) passes variadic arguments on the stack. That incompatible fixed-mode declaration remains unknown.

Storage ownership comes only from retained actual stack-root certificates: canonical physical slots and stack allocations, with their original byte extent. A derived pointer is not a new allocation. Selected projections and constant offsets stay relative to that root; every load, store and initialization must fit its original extent. Unknown extents, dynamic offsets and oversized type reinterpretations yield unknown. Source locals, default initializers and the attribution-only `stack_places` list cannot create private storage.

## Relations and identity

A capability records its result position, optional checked byte slot within an aggregate, native resource kind, validity condition and acquisition template. Templates contain `(procedure, block, event)` chains instantiated at each caller. They are not unique dynamic handles.

Per-block alternatives keep immutable scalar values, captured private slots and branch predicates together. Stores replace overlapping byte slots. An aggregate overwrite clears prior destination facts even when its source is unsupported. Exposing a canonical stack root is persistent: later unknown calls invalidate its stored contents without needing the address again. Captured immutable SSA copies remain distinct from those contents and still require native-liveness noninterference. Aggregate copies capture contents, so later source replacement does not change the copy. Formal substitution uses checked argument indices rather than source argument order. Pointer copies retain a capability only under the sidecar's same-address semantics. Nonzero `#as` pointer adjustments are selected field projections, so casting an adjusted pointer back to an opaque native handle cannot recover the original capability. Passing through an incoming handle creates no fresh capability.

For example, returning `fopen`'s result and `handle != null` exports a stream plus a correlated success result. The real `File.file_open` carrier returns the native capability through its checked aggregate field. An unrelated success flag establishes no guard.

Comparisons retain their checked integer or pointer width. Both evaluated operands are masked to that width and signed predicates sign-extend afterward; unsigned high-bit constants do not become negative thresholds. Guard checking partitions values at every comparison constant and signed/unsigned boundary. It checks each partition, including failure sentinels. This is exhaustive for the supported comparison/boolean algebra rather than testing a few convenient values.

## Release and uncertainty

`fclose` invalidates the stream after either outcome, including a flush error; further use is unsupported. On Linux, `close` releases a valid descriptor before later I/O errors can be reported, so a failure status does not preserve its live capability. Other `close` targets remain unknown on failure until their native contract is established. These rules follow the [Linux close contract](https://man7.org/linux/man-pages/man2/close.2.html) and [fclose contract](https://man7.org/linux/man-pages/man3/fclose.3.html).

`CloseHandle` success consumes the handle. Its zero failure status alone does not certify retained liveness. Windows documents a [protected-from-close flag](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-sethandleinformation) that can prevent closure, but this domain does not prove that flag state or a general retention guarantee from [CloseHandle failure](https://learn.microsoft.com/en-us/windows/win32/api/handleapi/nf-handleapi-closehandle). Failure therefore exports unknown, not a fresh live result or a must-close fact.

Consumption and uncertain disposition are separate internal effects. Both block an unsupported live-return witness, but uncertainty never becomes proof of closure. Native kind requirements travel with these effects. Copies share acquisition identity, while a later acquisition remains a distinct template even if a numeric value is reused.

An authenticated GNU/Linux [`fcloseall`](https://man7.org/linux/man-pages/man3/fcloseall.3.html) invalidates all existing stream capabilities, including copies held only in private locals. An ordinary unknown call can also change global native lifetime without receiving a handle argument. Private scalar storage proves only preserved bits.

Each returned capability therefore carries `requires_noninterference` sites, and `Opening.incomplete` is true when any such obligation remains. A site can name an enclosing checked call and covers that invocation's unmodeled effects. Consumers must prove preservation of the particular acquisition at every required site before calling it live; an incomplete origin is not a live-object guarantee. The native value/sentinel guard alone cannot supply that proof. Real host/Windows `File.file_open` origins retain explicit obligations for allocator callbacks after acquisition, so source-note removal still needs a consumer frame proof.

Global effects apply to acquisitions already present at the event. A later acquisition is independent. Typed release effects also account for numeric aliases under checked guards: `h == 3` makes `close(3)` target `h`, while `h != 3` can exclude it. Numeric equality does not create freshness. Distinct acquisitions exclude alias only while both capabilities are proved simultaneously live; close/reuse or an unresolved frame prevents that shortcut.

Unknown calls, unsupported stores and transfers invalidate affected argument knowledge. Checked read-only predicates can preserve a resource while returning an unknown predicate. This uncertainty does not prove closure.

`opening(id)` returns possible fresh acquisition origins. A capability is a live-return witness only after its noninterference conditions are discharged. It does not guarantee opening on every path. `None` means no supported witness was established; consumers must never interpret it as purity, absence of acquisition or successful closure. Missing alternatives can include opaque calls, unsupported output parameters and cutoffs.

## Bounds and changes

The domain bounds alternatives, transfer work, projection depth and call-template depth. Capability extraction preflights the complete exit/predicate/sample product in `proof.rs`, with 4,096 expression nodes, 4,096 partition samples and 8,388,608 estimated work units. The partitions are shared only within that extraction. Exceeding a limit discards the whole opening; expensive alternatives are never silently omitted. Inner predicate loops also poll cancellation. Global liveness propagation has a 65,536-token visit budget and at most 16 noninterference sites per token; exhaustion discards unsupported witnesses. Boolean trees also have independent node/depth budgets in `scalar_handles/expression.rs`. Constructors compute the complete parent cost with checked arithmetic while borrowing operands, then clone only if it fits; exhaustion widens the expression to unknown. This prevents straight-line negation chains and duplicated subexpressions from growing beyond CFG limits. Recursive summary queries, repeated CFG blocks and exhausted bounds return unknown. In particular, a repeated loop site does not become one unique handle. Supporting those loops requires a recency domain.

Extend native protocols in `native`, with ABI and sentinel counterexamples. Extend checked transfers in `Solver::body`; keep byte slots typed and values captured across writes. Boolean producer facts belong in the compiler sidecar so inference survives executable IR release. Add positive and matched unknown/negative regressions before extending expression or projection support. Tests select fixture declarations by module and require a unique checked fallback for library carriers; an imported name collision must not make a control vacuous.

Pointer-output acquisitions, arbitrary pointer hops, descriptor indexing and general cyclic protocols remain incomplete. By-value aggregate substitution with multiple actual arguments is also unknown until the sidecar certifies a distinct evaluation-time copy; rereading its source at the call could observe a later argument's mutation. Returned-capability inference does not establish guarded field-output relations. `scalar_openings.rs` indexes agreed checked call results once per lint invocation. A separate bounded caller pass captures the actual post-call native expression and follows the same release, alias and noninterference effects to applicable exits. Captures are separate from ordinary return results and never enter the callee-summary cache. A missing, unknown, invalid, framed or returned acquired exit rejects the inferred opening; returning one alias transfers that token's obligation for every alias. a feasible valid live witness is required. This handles global stream closure and constant-handle aliases without requiring a mention of the local. Closing one independent result can preserve another's obligation. Caller analysis permits at most 64 probes and bounds guard classification work; unsupported loops and exhausted work stay unknown. `unclosed_resource` uses only complete returned capabilities without pending noninterference sites; incomplete real file carriers retain their declared contracts. A handle in result one selects the second local in `ok, handle := acquire()`. Multiple unhandled results use their distinct declaration-name locations; single acquisitions retain the call location. Native return acquisition never implies that the first argument was opened. Missing or disagreeing checked instances stay unknown. Integration preserves the rule: report a local that nothing closes or transfers, without requiring closure on every path.

## Configuration and dependencies

Cancellation is polled while selecting procedures, entering blocks, transferring events, substituting callee alternatives and producing capabilities and propagating global liveness effects. A canceled build discards all partial openings; it cannot publish a partially populated result.

There is no user-facing option or persistent cache. An analysis belongs to one compiler generation and depends on the selected target, checked procedures, foreign ABI metadata, typed layouts and lifetime events.

Internal tests cover authentication, descriptor zero, guard copies/inversion, separate acquisitions, stale copies, paired successful/failed closes, mismatched native kinds, cancellation, aggregate snapshots, unknown effects and real checked host/Windows file carriers. Run focused debug tests with `cargo nextest run -p jailint scalar_handles`, a distinct `CARGO_TARGET_DIR` and `JAIC_STDLIB` set to the checkout's standard library. Checking these relations does not execute a native program.

The unclosed-local consumer probes callers only when they contain a checked call from a requested source file. It still computes ordinary callee relations with the same invocation-local solver and checks all instances of a reported source span. Empty source selection and an exhausted selection scan include all relevant bodies conservatively. A source-header filename alone is not the query key; the selected call span is. This changes which caller reports are computed, not native effects or closure policy.


Cached relations store compact normal-exit records, not mutable solver states. SSA values, memory slots, original-root certificates, exposure sets and traversal counters are dropped when an exit is captured; returns, predicates, release effects, validity/frame requirements and caller probes remain. Every reached exit still counts against exploration bounds before equivalent exported alternatives are deduplicated. This can reduce later caller work without changing the callee's cutoff policy. An exhausted liveness proof cannot become a published exit.
