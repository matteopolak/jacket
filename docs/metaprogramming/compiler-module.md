# Compiler module and compiler records

## What it is

`stdlib/Compiler/` declares the public metaprogramming API: workspaces, build settings, compiler messages, editable syntax records, reflection, and managed global data. Public `#compiler` operations run in Rust, independently of Jai procedure bodies in the selected standard library.

## How it works

`contract-records.jai` defines public data records. `workspace.jai` declares compiler operations without bodies, except `get_type`, `get_type_table`, and `get_runtime_info`, whose bodies implement their runtime behavior. Ordinary formatting and construction helpers remain Jai in `internal/compiler-api`.

The procedure's explicit selector (`#compiler "compiler_create_workspace"`), or its name when no selector is supplied, selects an `Operation` in `crates/jaic/src/build/public_api`. Binding checks the declaration against the operation's slots (`binding::slots`): each parameter and result's kind, what its pointers point at, its view elements, and the fields the handler reads or writes in its records, with their kinds and widths (`Schema::require`; the options records' fields come from `options::fields`). `JAIC_STDLIB` can select a different stdlib, so a declaration that does not fit is a compile error at the declaration rather than a failure inside a handler. Binding then resolves the declaration's actual record fields, offsets, sizes, defaults, and enums. Host handlers use this schema rather than offsets from one bundled stdlib. Records the host looks up by name (`Code_Node`, `Message_Complete`, `Type_Info`, ...) come from the modules that own the declaration's records, plus the prelude; a name those modules declare as two different types is an error at binding. Declarations that read the same modules share one `Rc<Schema>` (`binding::Shared`, kept in `public_api::State`), extended in place when a declaration brings a type the shared one lacks, and rebuilt when one of the modules gains declarations.

At compile time, `Hook::PublicCompiler` dispatches to the Rust handler and the existing workspace engine. At runtime, the interpreter and native backend execute a supplied Jai body. A bodyless operation reports that it is compile-time only. Unknown compiler operations fail explicitly at compile time.

### Options and messages

Rust stores full option snapshots, including owned strings and string arrays. Defaults come from the declaration's own record: `get_build_options` reads its declared return type, whatever it is named, and `set_build_options_dc` the `Build_Options` its owning module declares (`Binding::options`). Relative import paths use the caller location. During-compile updates append linker arguments and update output controls without replacing other settings. Unsupported backend options report a diagnostic; see [build options](build-options.md).

Interception advances workspaces fairly. Neutral record payloads become public message records using resolved layouts. PHASE and COMPLETE messages and their copied strings live until the interpreter is destroyed. Once all intercepted workspaces finish, waiting returns the last COMPLETE message. Internal event numbers and public message-kind values are separate contracts.

### Records and edited code

A target workspace exports neutral records (`crates/jaic/src/records.rs`), keyed by record id and named fields. `record_build.rs` materializes them into the calling program's declared types and preserves pointer identity. Promoted members are flattened; inline records, views, resizable arrays and fixed arrays use their actual layouts. Ambiguous nested type names use the expected field type instead of registration order. Primitive type descriptors preserve identity with the caller's descriptors.

`compiler_get_nodes` may request typed export and replay a pure compile-time run. Once observable effects have occurred, it uses the available untyped graph. Existing scope and replay handling is shared with the workspace engine.

`compiler_get_code` converts the current editable public graph straight into a syntax tree (`public_api/convert.rs`), with no source text or reparse. `compiler_modify_procedure` does the same for every current statement, including edits to existing nodes, then queues replacement and re-lowering at the next workspace step. The converter spells a text while it walks (names, literals, operators) that the tree's spans point into; it becomes a virtual source (`compiler_get_code N`, `compiler_modify_procedure N`) when the compiler adopts the tree, so diagnostics quote it. `convert/expr.rs`, `stmt.rs`, `decl.rs` and `directive.rs` hold the per-form mappings. Both APIs diagnose unsupported or incomplete syntax rather than silently discarding edits. `Program_Print` is the only printer. Syntax attributes absent from public record layouts remain compiler-owned metadata.

Handlers decode each operation's arguments through the bound declaration's layouts, then call typed engine functions (`build/engine.rs`: `Workspaces` methods plus the few that step a workspace or touch the interpreter). Records are planned for `record_build.rs` as typed `PlanEntry` lists, one per declared record type. Whether an operation is an observable effect, which decides whether a compile-time run can be replayed, is `Operation::is_effect`; waiting for a message counts only when it steps a workspace.

The three `__jaic_syntax_int`, `__jaic_syntax_string`, and `__jaic_syntax_child` extensions remain for `Program_Print`; they are the only `MetaOp` values.

## How to change it

Add or extend an operation in `build/public_api/mod.rs`, its slots (and the record fields its handler uses) in `binding::slots`, and its handler in `operations.rs`, `options.rs`, `messages.rs`, `records.rs`, or `convert.rs`, plus `Operation::is_effect` if it only reads. A handler that starts reading a new field of a slot's record should list it there too; the syntax records `convert.rs` and `messages.rs` walk by name are still checked only as they are read. What it does to workspaces belongs in `build/engine.rs`, with typed arguments. Update public declarations and test both bodyless compile-time dispatch and supplied runtime bodies.

New record members need exporter fields and a declared layout, not handwritten offsets or a Jai registration list. New syntax forms need a mapping in `convert/` and, when printable by `Program_Print`, its Jai printer. Keep syntax metadata keys synchronized as described in [compiler builtins](../compiler/compiler-builtins.md).

## Configuration

The selected stdlib/prelude provides declarations and defaults. Target flags determine `OS`, `CPU`, and default options. Workspace output requires an embedder backend; `-check` and `-no_workspace_output` do not emit workspace programs.

## Dependencies

The sema type system, interpreter memory checking, public prelude records, neutral record exporter, workspace engine, and the embedder's file system and output backend. Tests cover `stdlib/Compiler/tests`, compiler regressions, and `crates/jaic-cli/tests/compiler_primitives.rs`.

## Rules

Claims that tests cite by ID (`tools/dev/check_rule_coverage.py`).

- Rust owns the workspace option snapshots. Every workspace starts from the selected declaration's struct defaults {#compiler.3}, reflecting the target (`os_target := OS`, `cpu_target := CPU`) {#compiler.1}; the running workspace also gets the top-level compile-time command line {#compiler.2}.
- `get_build_options(w)` returns the stored copy {#compiler.4}.
- `set_build_options(options, w, loc)` validates supported settings, forwards them to the workspace engine, and snapshots the full record. Relative `import_path` entries are anchored at `loc`'s directory {#compiler.5}.
- `set_build_options_dc(dc, w, loc)` updates the stored copy and forwards `do_output`, `append_executable_filename_extension`, the output name and path, and one `additional_linker_argument` per `append_linker_arguments` entry {#compiler.6}.
- Destroying a workspace releases its engine state. Empty declaration defaults do not replace engine-derived output names and search defaults {#compiler.7}. Unsupported options are described in [build options](build-options.md).
- Once every intercepted workspace has finished, later calls keep returning a `COMPLETE` for the last one, with its error code, so the usual `if m.kind == .COMPLETE break;` loop terminates {#compiler.8}.
- Message records and copied strings remain valid for the lifetime of the interpreter. `Message.workspace` is always the workspace the event came from {#compiler.9}.
- `compiler_report(message, loc, mode)` reports through the workspace engine with the `Report` value. An `ERROR` report stops the metaprogram and fails the compile {#compiler.10}; `WARNING` and `INFO` print and do not fail it {#compiler.11}; `ERROR_CONTINUABLE` prints an error, lets the metaprogram go on and fails the build.
- `compiler_set_workspace_status(.FAILED, w)` marks failure so the build exits nonzero {#compiler.12}; `.OK` on a workspace that did not fail changes nothing {#compiler.13}, and cannot clear a failure.
- `compiler_get_version_info` returns the compiler version text and fills `major`, `minor`, and `micro` from `LANGUAGE_VERSION` {#compiler.14}.
- `compiler_set_type_info_flags(type, flags)` queues the flags (`Interp.pending_type_flags`); after each `call_thunk`, `apply_type_info_flags` merges them and rebuilds the descriptor. `NO_TYPE_INFO` empties `members` {#compiler.20}; `PROCEDURES_ARE_VOID_POINTERS` reports procedure members as `*void` {#compiler.21}.
- `get_name(w)` uses names remembered by `compiler_create_workspace` {#compiler.18}. `get_runtime_info` reads `__runtime_info` {#compiler.19}; asking for another workspace's is an error. In compile-time code `get_type_table(w)` instead lists a descriptor of every type the workspace has declared or used so far, unused structs and enums included {#compiler.29}. The table is built on demand, in `refresh_type_table` (`sema/runtime_info.rs`): it resolves the plain structs and enums declared at file level (one that cannot be resolved yet is left out), gives each type a descriptor with `type_info_global` and keeps the descriptors' addresses in a vector the interpreter owns (`ct_type_table`). The running workspace's table is made when a compile-time run that can reach `get_type_table` starts; another workspace's is made at the call from its compiler, which a workspace keeps after `COMPLETE` once any compile-time code references the primitive (`get_type_table` or `get_runtime_info`). Descriptors made only for the table stay out of the running program's own table until something else asks for them. In a compiled program `get_type_table` still returns the types the program reaches.
- An API call jaic cannot carry out reports a fatal error when it is made, never silently nothing {#compiler.17}: `add_build_string(text, w, code)` with a `Code` value from another workspace (code for the running workspace is added in that code's scope), `compiler_set_workspace_status(.OK)` on a failed workspace, and `add_global_data` with `.USER_SEGMENT` but no segment.
- `remap_import(w, host, name, replacement)` makes `#import "name"` in module `host` (empty: any module) load `replacement`; the latest rule wins, and imports resolved before the call keep their module {#compiler.23}.
- `provide_import(w, message, type, value)` answers a `FAILED_IMPORT` message with a module name, a file, a directory holding `module.jai` or the source text (`Provided_Import_Type`) {#compiler.24}. jaic delivers the message after the load failed, so a workspace with a `FAILED_IMPORT` and an intercepting metaprogram is held back: it keeps the error unreported until the metaprogram next asks for a message, and if an offer arrived by then the workspace loads its sources again from scratch (new compiler, same sources) using it. An offer identical to one already made does not count (the retry would fail the same way, and a metaprogram answering every `FAILED_IMPORT` with it would loop for ever; test: `fuzz/regressions/check/provide-import-missing-file.jai`). Without an offer the error is reported, followed by `ERROR` and `COMPLETE` as before (`build::resume_failed_load`).
- `compiler_make_procedure_live(w, header)` keeps the procedure of a header the workspace sent, though nothing calls it: the header's record maps to its procedure (`Compiler::make_procedure_live`), which `lower_reachable_inner` lowers with the program's exports. It matters under `dead_code_elimination = .ALL`; the default modes already check and keep program procedures. Headers of polymorphic procedures and macros are ignored {#compiler.25}.
- `get_root_type(code)` returns `SUCCESS` with the typed root, `INPUT_IS_CODE_NULL` for null code, or `NOT_TYPED` {#compiler.26}. `compiler_get_base_path()` is the directory above `stdlib`. `add_data_segment` returns a managed handle and `false` for an actual named section. Compiler memory breakpoints and debugger requests fail explicitly {#compiler.27}.
- `compiler_add_library_search_directory(path)` adds a directory searched for `#library` names (compile-time `dlopen` and the link line), ahead of the driver's. It is process-wide, not per workspace; the directory is not added to the executable's run path, so a shared library there still has to be found by the loader at run time {#compiler.28}.
- Syntax-tree APIs (`compiler_get_nodes`, `compiler_get_code`, `code_to_string`, `print_expression`, `add_global_data`, `compiler_modify_procedure`) are in [compiler records](compiler-module.md) {#compiler.15}. `add_build_string(text, w, message)` with a FILE or IMPORT message adds the text to that message's module; otherwise it goes to the workspace's top level {#compiler.16}. `add_build_string(text, w, code)` with a non-null `code` adds the text in that code's scope ; the code must belong to the running workspace. `compiler_get_struct_location` gives the file, line and column where a struct is declared  {#compiler.22}.
- `export_file_events`: an IMPORT record per module before its first file {#records.1}, and a FILE record per file {#records.2}. Module types: Preload is `PRELOAD`, Runtime_Support `RUNTIME_SUPPORT`, the main module `MAIN_PROGRAM`, the rest `UNINITIALIZED` {#records.3}. Hidden `__module`/`__file` fields let `add_build_string(.., message)` find the module.
- `export_typechecked`: every new top-level declaration of a user module is resolved and exported with its type {#records.4}. User means not Preload or Runtime_Support and not under the system module directory (the directory of `Runtime_Support.jai`). Procedure headers, bodies and struct literals inside go into `procedure_headers`, `procedure_bodies` and `structs`, and every node into `subexpressions`. Declarations that fail to resolve are skipped, where Jai would report an error.
- Global declarations, parameters and returns, and type instantiations get `type` {#records.5}; local declarations and other expressions don't. A variadic parameter's `type_inst` has `inst_flags = .VARARGS` (`mark_varargs`, in both the reported header and the resolved one); Check's @PrintLike test looks for it before the format string. Test: `tests/compiler/regressions/code-export-varargs-flag.jai`. Notes after a procedure body attach to the declaration and the header {#records.6}. `Code_Node.serial` is the record id.
- `type_record` makes Type_Info records, memoised per `TypeId`. Primitive types carry `__builtin` (their name) so the metaprogram substitutes its own descriptor and `decl.type == type_info(int)` works {#records.7}. Polymorphic struct instances get `specified_parameters`, `constant_storage` and a generic `polymorph_source_struct` {#records.8}; `Type` parameters are pointers the Rust record builder patches from `__constant_pointers`.
- A top-level enum's `Code_Enum.external_type` is its `Type_Info_Enum` {#records.26}.
- `-1` and `-1.5` export as one negative `Code_Literal`, as Jai folds them (yield-jai overwrites `_s64` of `#code case -1`) {#records.14}.
- Backticked identifiers and declarations set `HAS_SCOPE_MODIFIER` {#records.15}. `#assert` and `#run` statements export as `Code_Directive_Run` (with jaic's extra `expression` and `message`) {#records.16}, `#exists(x)` as `Code_Directive_Exists` {#records.17}.
- `a, b := f()` is a `Code_Compound_Declaration`: the names in `comma_separated_assignment`, the shared type and values in a nameless `declaration_properties` {#records.20}.
- A procedure whose body isn't lowered yet is reported with a null `body_or_null` and queued in `ExportState::pending_bodies`. Each later `export_typechecked` reports the bodies lowered since, with local declaration types, and patches the header's `body_or_null`. The Jai side also patches the cached header struct, since a metaprogram may still hold it from the earlier message (MetaThreadSafe checks bodies at COMPLETE). An imported module's bodies that nothing reaches are never lowered, so they are never reported and their errors never surface, matching Jai's default dead-code elimination {#records.28}. The program's own unreferenced bodies are type-checked once the workspace has finished ([dead-code elimination](../language/dead-code-elimination.md)); `build::step` then sends one more TYPECHECKED message with those bodies right before the closing phases and COMPLETE, so a metaprogram that walks `procedure_bodies` also sees procedures nothing calls (it can no longer add code in reaction to them). Declarations of file-level names carry `IS_GLOBAL`, and `SCOPE_FILE` below a `#scope_file` {#records.32}.
- Exception: noted procedures (`@glsl`, `@thread`, on the header or after the body) whose headers went out are lowered leniently once the workspace runs out of sources (`lower_reachable_inner`), because metaprograms find shaders and checked procedures by note whether or not anything calls them (Jai-Shader-Transpiler). Only procedures in the main module qualify {#records.22}. An imported module's uncalled noted procedures stay unchecked {#records.23}, since imported modules ship stale ones: Vk-Engine's `@PrintLike FormatToCString` calls a procedure that doesn't exist.
- `ExportState::resolved_headers` keeps one header record per procedure, shared by `resolved_procedure_expression` and the reported header, so a checker following calls reaches bodies {#records.24}. The key includes `Exporter::own`: a compiler's own compile-time code (`#modify`) needs type records with real descriptors, which exports for a metaprogram don't have. Resolved headers carry the procedure's notes, including those after the body (`Compiler::pr.proc_decl_notes`, copied to polymorph instances), and list `using` parameters in `parameter_usings` {#records.25}.
- A call to a polymorphic procedure resolves to the instance it made, not the generic procedure: sema records the instances each call span made (`ExportState::call_instances`, filled in `match_candidate`), and `Exporter::instance_called_at` picks the one belonging to the resolved procedure {#records.30}. The instance's header has no `POLYMORPHIC` flag, and its body is reported in a later TYPECHECKED message once lowered, exported in the scope of its bindings. A static `#if` there has `static_if_flags` `EVALUATED_AS_TRUE` when the condition held, and a static `if x == {` switch has `static_if_accepted_case`, so a checker can follow only the branch the compiler took (MetaThreadSafe does) {#records.31}. In a generic body the condition is unknown and neither is set.
- When a workspace runs out of sources, `step` lowers everything reachable (`Compiler::lower_reachable`, lenient: a failing body stays queued). If that reports new declarations or bodies (a body can declare more through `#insert,scope(...)`), the metaprogram gets another `TYPECHECKED_ALL_WE_CAN` and may add code {#records.27}. Only a round that reports nothing new proceeds to `finish_program` and code generation.
- The Rust record builder resolves declared member layouts, flattening promoted fields and materializing scalar, string, pointer, inline-record and array fields. A record maps to one pointer {#records.9}. Public node defaults set the node kind for user-created records {#records.19}.
- Libraries like or_return, MetaThreadSafe and Jai-Shader-Transpiler read `Code_Procedure_Call.resolved_procedure_expression`, `Code_Ident.resolved_declaration` and `Code_Node.type` {#records.10}. Those need the compiler, which a compiler operation can't reach while the interpreter runs. So jaic traps and reruns:
- Value expressions get `type` by checking them in the code's scope without emitting (`Exporter::expr_type`). One that reads a local (`Exporter::reads_local`) gets none, since the code's scope does not have the local. Untyped literals report their default (`s64`, `float32`) {#records.13}.
- Type records carry `__address`, the real descriptor in this program's memory, so `type == type_info(T)` works {#records.11}.
- Rust converts the current editable node graph into a new `Code`. Names resolve in the copied scope {#records.12}. Typed-export reruns replay a code when its conversion read the same values (a fingerprint of every field and attribute read; pointers count by presence) from the same scope, rather than allocating endlessly {#records.29}. Unsupported or incomplete syntax reports a diagnostic.
- Procedure edits convert every current statement, including edits to existing records, and are queued until the next workspace step. The compiler replaces and re-lowers the body, so the modified body runs {#records.18}.
