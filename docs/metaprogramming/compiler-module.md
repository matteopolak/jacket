# Compiler module and compiler records

## What it is

`stdlib/Compiler/` is jaic's implementation of Jai's public `Compiler` module (`#import "Compiler"`): metaprograms create workspaces, set `Build_Options`, add source, intercept compiler messages and report diagnostics. It is plain Jai over bodiless `#compiler` primitives (`__jaic_*`) bound by the Rust side ([workspaces](workspaces.md)). The second half covers the records that let a metaprogram see another workspace's code (`Message_*`, `Code_*` nodes, `Type_Info_*`, `compiler_get_nodes`, `compiler_get_code`, `compiler_modify_procedure`).

## How it works

`stdlib/Compiler/` is the public surface: `contract-records.jai` holds the data records (`Build_Options`, `Message_*`, the `Code_Node` family, `Code_Directive_*`; layout and member order follow the public API), and `workspace.jai` and `helpers.jai` only alias procedures from `stdlib/internal/compiler-api/`, which holds the implementation:

| File | Content |
| --- | --- |
| `workspaces.jai` | Workspaces, `add_build_file/string`, `get/set_build_options`, `compiler_report`, version info, `remap_import`, `provide_import` |
| `messages.jai` | Interception, `compiler_wait_for_message`, custom link completion |
| `records.jai` | `compiler_get_nodes/get_code/modify_procedure`, `get_type_table`, record plans |
| `registry.jai`, `data.jai`, `primitives.jai` | Per-workspace state, runtime info and data segments, the bodiless `#compiler` primitive declarations |

### Options

`set_build_options(options, w, loc)` forwards each field with a typed builtin (`__jaic_workspace_set_text/flag/number/list`, keyed by a `Workspace_*` enum; see [compiler builtins](../compiler/compiler-builtins.md)), anchors relative `import_path` entries at `loc`'s directory, and snapshots the full struct for other compilers (`snapshot_options`, `crates/jaic/src/build/option_snapshot.rs`). `get_build_options` returns that stored copy, so every workspace starts from the struct defaults, which reflect the target (`os_target := OS`, `cpu_target := CPU`). `set_build_options_dc` forwards `do_output`, the output name and path, and linker arguments. Features the compiler does not have fail with a `require` error naming them ([build options](build-options.md)).

### Messages

`compiler_begin_intercept(w, flags)` registers the workspace; `compiler_wait_for_message()` walks intercepted workspaces round-robin, calls `__jaic_workspace_next_event`, and builds the message: FILE, IMPORT and TYPECHECKED carry a record id in int 0 (materialised by `__jaic_rec_build`); PHASE carries the phase plus object/library lists for the write and link phases; COMPLETE carries `error_code`; ERROR and DEBUG_DUMP have their own shapes. After every workspace finishes, further calls keep returning COMPLETE so `if m.kind == .COMPLETE break;` terminates. PHASE and COMPLETE reuse one struct per kind, valid only until the next call.

### Reporting and stubs

- `compiler_report(message, loc, mode)` calls `__jaic_report`: `ERROR` stops the metaprogram, `WARNING`/`INFO` print, `ERROR_CONTINUABLE` prints an error and fails the build. `compiler_set_workspace_status(.FAILED, w)` reports a fatal diagnostic; `.OK` on a failed workspace is an error.
- `compiler_get_version_info` parses `__jaic_compiler_version()`. `compiler_set_type_info_flags` queues flags applied after each `call_thunk` (`NO_TYPE_INFO` empties `members`; `PROCEDURES_ARE_VOID_POINTERS`).
- `get_runtime_info` reads `__runtime_info`; another workspace's is an error. In compile-time code `get_type_table(w)` lists a descriptor of every type declared or used so far, unused ones included, built by `refresh_type_table` (`sema/runtime_info.rs`).
- An API call jaic cannot carry out reports a fatal error when made: `add_build_string(text, w, code)` with a `Code`, `.USER_SEGMENT` without a segment.
- `remap_import(w, host, name, replacement)` redirects an import (latest rule wins). `provide_import(w, message, type, value)` answers a `FAILED_IMPORT`: the workspace holds the error until the metaprogram next asks for a message, and if an offer arrived, reloads its sources with it (`build::resume_failed_load`); an identical repeat offer does not count, to avoid loops.
- `compiler_make_procedure_live(w, header)` keeps a header's procedure (`Compiler::make_procedure_live`), relevant under `dead_code_elimination = .ALL`. `get_root_type(code)` returns `SUCCESS`, `INPUT_IS_CODE_NULL` or `NOT_TYPED`. `compiler_add_library_search_directory` is process-wide. `compiler_report_errors_for_*` and `compiler_set_memory_breakpoint` do nothing, since jaic reports unresolved names where they occur and its interpreter has no write watch.

### Why records

A metaprogram runs in its own compiler's interpreter, and the target workspace's types are not the metaprogram's types. So the target's compiler exports neutral records (`crates/jaic/src/records.rs`): a tag naming a Jai struct (`"Code_Ident"`, `"Type_Info_Struct"`) and named fields (`Int`, `Str`, `Ref`, or lists). Ids are global to the compilation and never repeat (the builder keeps one struct per id). A `Record` is compact (16-byte `Slot`s with interned field names) because exported trees dominate a metaprogram compiler's memory.

### Rust exporter

`sema/code_export.rs`, state in `Compiler::export`:

- `export_file_events` sends an IMPORT record per module and a FILE record per file (module types `PRELOAD`, `RUNTIME_SUPPORT`, `MAIN_PROGRAM`, else `UNINITIALIZED`).
- `export_typechecked` exports every new top-level declaration of a user module (not Preload, Runtime_Support or the system module directory) with its type, plus procedure headers, bodies, structs and `subexpressions`. Declarations that fail to resolve are skipped. Global declarations, parameters, returns and type instantiations get `type`; locals do not. Variadic parameters have `inst_flags = .VARARGS`. Notes after a body attach to the declaration and header.
- `type_record` memoises `Type_Info` records per `TypeId`; primitives carry `__builtin` so `decl.type == type_info(int)` works. Polymorphic instances get `specified_parameters`, `constant_storage` and `polymorph_source_struct`. `-1` exports as one negative `Code_Literal`; backticks set `HAS_SCOPE_MODIFIER`; `#assert`/`#run` export as `Code_Directive_Run` (with jaic's extra `expression`, `message`); `a, b := f()` is a `Code_Compound_Declaration`.
- `build::step` takes the record table out of the registry while exporting (resolving can run compile-time code); `Records::lend` / `give_back` keep ids unique across nested exports.
- A procedure whose body is not lowered yet is reported with null `body_or_null` and patched in a later TYPECHECKED message (`ExportState::pending_bodies`), including the cached Jai header. Imported-module bodies nothing reaches are never reported, matching Jai's default elimination. The program's own unreferenced bodies come in one last TYPECHECKED message before the closing phases ([dead-code elimination](../language/dead-code-elimination.md)). Noted procedures (`@glsl`, `@thread`) in the main module are lowered leniently when sources run out, because metaprograms find them by note; imported modules' uncalled noted procedures stay unchecked since they ship stale ones.
- A call to a polymorphic procedure resolves to the instance it made (`ExportState::call_instances`, `instance_called_at`); static `#if` and `if x ==` nodes carry `static_if_flags` / `static_if_accepted_case`.
- When a workspace runs out of sources, `step` lowers everything reachable (`lower_reachable`); if that reports new declarations, the metaprogram gets another `TYPECHECKED_ALL_WE_CAN` before `finish_program`.

### Jai side

Building is native (`crates/jaic/src/record_build.rs`): `describe_members` in `internal/compiler-api/records.jai` flattens each struct's members into `Record_Plan_Entry`s passed with `__jaic_rec_plan`, and `__jaic_rec_build` builds a record and everything it reaches with a work list into zeroed chunks, memoised so a record maps to one pointer forever; `record_id` maps a pointer back. Adding a member kind needs a plan kind (`plan_kind`) on both the Jai and Rust sides.

### `compiler_get_nodes`, `compiler_get_code`, `compiler_modify_procedure`

`__jaic_code_nodes` exports a `Code` value. Libraries like or_return and MetaThreadSafe read `resolved_procedure_expression`, `resolved_declaration` and `Code_Node.type`, which need the compiler. So jaic traps and reruns: `call_thunk` counts observable effects (`Interp::effects`: output, foreign calls, workspace operations); while none has happened, `__jaic_code_nodes` traps with `Interp::export_request`, `call_thunk` exports with `export_code_typed` and reruns the thunk. A run that already did something gets untyped nodes (and a run that writes globals before the call writes them again on the rerun). Names resolve to locals first, then `Compiler::lookup`; non-scope names (members, labels, named arguments) export unresolved (`name_ident`); type records carry `__address` so `type == type_info(T)` works. A compile-time run inside another body's lowering lowers only what its thunk reaches (`lower_reachable_from`) and reruns on `Interp::missing_func`.

`compiler_get_code` prints the tree with `Program_Print`, then `__jaic_parse_code` parses it (`build::parse_code_text`) into a new code; node edits the printer cannot express are lost ([Program_Print](../specs/stdlib/modules/program-print.md)). Names resolve where the original was written, or, without `code_to_copy_scope_from`, at the insertion site with fallbacks to scopes of codes given to `compiler_get_nodes` (`Compiler::code_scope_at`, `Scope::fallbacks`). Reruns replay earlier made codes (`Interp::run_codes`) so `code_to_string(compiler_get_code(root))` finishes.

`compiler_modify_procedure` sends, per top-level statement, a record id or (0 plus `Program_Print` text) for new or edited statements (compared against what the record builder wrote). The edit is queued and applied at the next step (`Compiler::modify_procedure`), replacing the `ProcLit` and re-lowering it if already lowered (`relower_modified`). Only top-level statement lists can be modified.

## How to change it

- New forwarded option: add the field to `Build_Options` in `contract-records.jai` (keep member order and defaults), forward it in `set_build_options` (`workspaces.jai`), add the member to the `Workspace_*` enum and `crates/jaic/src/builtin_keys.rs`, and handle it in `Workspaces` (`build.rs`), update [build options](build-options.md).
- New event kind: an `EVENT_*` constant in `build.rs` and a case in `compiler_wait_for_message` (`messages.jai`); prefer a record payload.
- New primitive: a `MetaOp` in `build.rs` plus a `#compiler` declaration in `primitives.jai`; keep public signatures, and for something jaic cannot do either do nothing with a comment or report through `__jaic_report`.
- New node kind: a case in `Exporter::expr`/`stmt` building a record with the `Code_*` member names (and a `RECORD_TYPES` entry if reached through a base pointer). Never hold the registry borrow while exporting.
- Workspace id `-1` means the current workspace. `jaic -check` only checks code reachable from `main`, so probes must call new procedures behind a runtime condition.

Tests: `tests/stdlib/type-info-flags.jai`, `compiler-typechecked-messages.jai`, `compiler-resolved-nodes.jai`, `compiler-get-code.jai`. Configuration: `jaic file.jai -check -os linux|windows|macos` changes the target `OS`. Depends on the `__jaic_*` primitives in `build.rs`, prelude types (`Workspace`, `Source_Code_Location`, `Type_Info*`), and `sema` resolution; in-repo users include `Default_Metaprogram`, `Metaprogram_Plugins` and `stdlib/internal/build/`.

## Rules

Claims that tests cite by ID (`tools/check_rule_coverage.py`).

- Jai owns `Build_Options` storage: `option_store` is indexed by workspace id and filled lazily by `ensure_option_slot`. Every workspace starts from the struct defaults {#compiler.3}, which already reflect the target (`os_target := OS`, `cpu_target := CPU`) {#compiler.1}; the metaprogram's own also gets `compile_time_command_line` from `__jaic_command_line_*` {#compiler.2}.
- `get_build_options(w)` returns the stored copy {#compiler.4}.
- `set_build_options(options, w, loc)` stores it, reports what jaic does not act on (`check_build_options`, see [build options](build-options.md)) and forwards settings with the typed `__jaic_workspace_set_*` builtins. Changed relative `import_path` entries are anchored at `loc`'s directory {#compiler.5}.
- `set_build_options_dc(dc, w, loc)` updates the stored copy and forwards `do_output`, `append_executable_filename_extension`, the output name and path, and one `additional_linker_argument` per `append_linker_arguments` entry {#compiler.6}.
- `compiler_destroy_workspace` sends `destroy` (empty value). Only changed or non-empty values are forwarded for settings the Rust side defaults itself (output name, import paths, optimization, dead code elimination), so empty Jai defaults never clobber them. That is why the default `import_path` is empty {#compiler.7}. `write_added_strings` is not forwarded; [build options](build-options.md) says why.
- Once every intercepted workspace has finished, later calls keep returning a `COMPLETE` for the last one, with its error code, so the usual `if m.kind == .COMPLETE break;` loop terminates {#compiler.8}.
- PHASE and COMPLETE messages reuse one module-level struct per kind, so they and their strings are valid only until the next `compiler_wait_for_message()`. That matches the event payload strings, which aren't copied. `Message.workspace` is always the workspace the event came from {#compiler.9}.
- `compiler_report(message, loc, mode)` calls `__jaic_report` with the `Report` value. An `ERROR` report stops the metaprogram and fails the compile {#compiler.10}; `WARNING` and `INFO` print and do not fail it {#compiler.11}; `ERROR_CONTINUABLE` prints an error, lets the metaprogram go on and fails the build.
- `compiler_set_workspace_status(.FAILED, w)` has no primitive: unless `w` already failed it reports a fatal diagnostic so the exit code is non-zero {#compiler.12}. `.OK` on a workspace that did not fail changes nothing {#compiler.13}; on one that failed it is an error.
- `compiler_get_version_info` returns `__jaic_compiler_version()` and parses the first digit run (`"Jacket 0.18.0"` gives 0, 18, 0) {#compiler.14}.
- `compiler_set_type_info_flags(type, flags)` queues the flags (`__jaic_set_type_info_flags`, `Interp.pending_type_flags`); after each `call_thunk`, `apply_type_info_flags` merges them and rebuilds the descriptor. `NO_TYPE_INFO` empties `members` {#compiler.20}; `PROCEDURES_ARE_VOID_POINTERS` reports procedure members as `*void` {#compiler.21}.
- `get_name(w)` uses names remembered by `compiler_create_workspace` {#compiler.18}. `get_runtime_info` reads `__runtime_info` {#compiler.19}; asking for another workspace's is an error. In compile-time code `get_type_table(w)` instead lists a descriptor of every type the workspace has declared or used so far, unused structs and enums included {#compiler.29}. The table is built on demand, in `refresh_type_table` (`sema/runtime_info.rs`): it resolves the plain structs and enums declared at file level (one that cannot be resolved yet is left out), gives each type a descriptor with `type_info_global` and keeps the descriptors' addresses in a vector the interpreter owns (`ct_type_table`). The running workspace's table is made when a compile-time run that can reach `get_type_table` starts; another workspace's is made at the call from its compiler, which a workspace keeps after `COMPLETE` once any compile-time code references the primitive (`__jaic_type_table`). Descriptors made only for the table stay out of the running program's own table until something else asks for them. In a compiled program `get_type_table` still returns the types the program reaches.
- An API call jaic cannot carry out reports a fatal error when it is made, never silently nothing {#compiler.17}: `add_build_string(text, w, code)` with a `Code` value, `compiler_set_workspace_status(.OK)` on a failed workspace, and `add_global_data` with `.USER_SEGMENT` but no segment.
- `remap_import(w, host, name, replacement)` makes `#import "name"` in module `host` (empty: any module) load `replacement`; the latest rule wins, and imports resolved before the call keep their module {#compiler.23}.
- `provide_import(w, message, type, value)` answers a `FAILED_IMPORT` message with a module name, a file, a directory holding `module.jai` or the source text (`Provided_Import_Type`) {#compiler.24}. jaic delivers the message after the load failed, so a workspace with a `FAILED_IMPORT` and an intercepting metaprogram is held back: it keeps the error unreported until the metaprogram next asks for a message, and if an offer arrived by then the workspace loads its sources again from scratch (new compiler, same sources) using it. An offer identical to one already made does not count (the retry would fail the same way, and a metaprogram answering every `FAILED_IMPORT` with it would loop for ever; test: `fuzz/regressions/check/provide-import-missing-file.jai`). Without an offer the error is reported, followed by `ERROR` and `COMPLETE` as before (`build::resume_failed_load`).
- `compiler_make_procedure_live(w, header)` keeps the procedure of a header the workspace sent, though nothing calls it: the header's record maps to its procedure (`Compiler::make_procedure_live`), which `lower_reachable_inner` lowers with the program's exports. It matters under `dead_code_elimination = .ALL`; the default modes already check and keep program procedures. Headers of polymorphic procedures and macros are ignored {#compiler.25}.
- `get_root_type(code)` is `SUCCESS` with the type of the typed root node (`Code_Node.type`), `INPUT_IS_CODE_NULL` for `#code,null`, and `NOT_TYPED` for code whose nodes were not typed (see [compiler records](compiler-module.md)) {#compiler.26}. `compiler_get_base_path()` is the directory above `stdlib` with a trailing slash. `add_data_segment` returns a handle and `false` for `actual_segment_will_be_created`, and `add_global_data` then places the bytes with the other constant data. `compiler_report_errors_for_unresolved_identifiers`, `compiler_report_errors_for_untyped_declarations_with_these_notes` and `compiler_set_memory_breakpoint` do nothing: jaic reports unresolved names as errors where they occur, checks every declaration of the program's own files by default, and its compile-time interpreter has no write watch {#compiler.27}.
- `compiler_add_library_search_directory(path)` adds a directory searched for `#library` names (compile-time `dlopen` and the link line), ahead of the driver's. It is process-wide, not per workspace; the directory is not added to the executable's run path, so a shared library there still has to be found by the loader at run time {#compiler.28}.
- Syntax-tree APIs (`compiler_get_nodes`, `compiler_get_code`, `code_to_string`, `print_expression`, `add_global_data`, `compiler_modify_procedure`) are in [compiler records](compiler-module.md) {#compiler.15}. `add_build_string(text, w, message)` with a FILE or IMPORT message adds the text to that message's module; otherwise it goes to the workspace's top level {#compiler.16}. `add_build_string(text, w, code)` with a non-null `code` is an error (`__jaic_code_is_null`). `compiler_get_struct_location` gives the file, line and column where a struct is declared (`__jaic_struct_location`) {#compiler.22}.
- `export_file_events`: an IMPORT record per module before its first file {#records.1}, and a FILE record per file {#records.2}. Module types: Preload is `PRELOAD`, Runtime_Support `RUNTIME_SUPPORT`, the main module `MAIN_PROGRAM`, the rest `UNINITIALIZED` {#records.3}. Hidden `__module`/`__file` fields let `add_build_string(.., message)` find the module.
- `export_typechecked`: every new top-level declaration of a user module is resolved and exported with its type {#records.4}. User means not Preload or Runtime_Support and not under the system module directory (the directory of `Runtime_Support.jai`). Procedure headers, bodies and struct literals inside go into `procedure_headers`, `procedure_bodies` and `structs`, and every node into `subexpressions`. Declarations that fail to resolve are skipped, where Jai would report an error.
- Global declarations, parameters and returns, and type instantiations get `type` {#records.5}; local declarations and other expressions don't. A variadic parameter's `type_inst` has `inst_flags = .VARARGS` (`mark_varargs`, in both the reported header and the resolved one); Check's @PrintLike test looks for it before the format string. Test: `tests/stdlib/code-export-varargs-flag.jai`. Notes after a procedure body attach to the declaration and the header {#records.6}. `Code_Node.serial` is the record id.
- `type_record` makes Type_Info records, memoised per `TypeId`. Primitive types carry `__builtin` (their name) so the metaprogram substitutes its own descriptor and `decl.type == type_info(int)` works {#records.7}. Polymorphic struct instances get `specified_parameters`, `constant_storage` and a generic `polymorph_source_struct` {#records.8}; `Type` parameters are pointers the Jai side patches from `__constant_pointers`.
- A top-level enum's `Code_Enum.external_type` is its `Type_Info_Enum` {#records.26}.
- `-1` and `-1.5` export as one negative `Code_Literal`, as Jai folds them (yield-jai overwrites `_s64` of `#code case -1`) {#records.14}.
- Backticked identifiers and declarations set `HAS_SCOPE_MODIFIER` {#records.15}. `#assert` and `#run` statements export as `Code_Directive_Run` (with jaic's extra `expression` and `message`) {#records.16}, `#exists(x)` as `Code_Directive_Exists` {#records.17}.
- `a, b := f()` is a `Code_Compound_Declaration`: the names in `comma_separated_assignment`, the shared type and values in a nameless `declaration_properties` {#records.20}.
- A procedure whose body isn't lowered yet is reported with a null `body_or_null` and queued in `ExportState::pending_bodies`. Each later `export_typechecked` reports the bodies lowered since, with local declaration types, and patches the header's `body_or_null`. The Jai side also patches the cached header struct, since a metaprogram may still hold it from the earlier message (MetaThreadSafe checks bodies at COMPLETE). An imported module's bodies that nothing reaches are never lowered, so they are never reported and their errors never surface, matching Jai's default dead-code elimination {#records.28}. The program's own unreferenced bodies are type-checked once the workspace has finished ([dead-code elimination](../language/dead-code-elimination.md)); `build::step` then sends one more TYPECHECKED message with those bodies right before the closing phases and COMPLETE, so a metaprogram that walks `procedure_bodies` also sees procedures nothing calls (it can no longer add code in reaction to them). Declarations of file-level names carry `IS_GLOBAL`, and `SCOPE_FILE` below a `#scope_file` {#records.32}.
- Exception: noted procedures (`@glsl`, `@thread`, on the header or after the body) whose headers went out are lowered leniently once the workspace runs out of sources (`lower_reachable_inner`), because metaprograms find shaders and checked procedures by note whether or not anything calls them (Jai-Shader-Transpiler). Only procedures in the main module qualify {#records.22}. An imported module's uncalled noted procedures stay unchecked {#records.23}, since imported modules ship stale ones: Vk-Engine's `@PrintLike FormatToCString` calls a procedure that doesn't exist.
- `ExportState::resolved_headers` keeps one header record per procedure, shared by `resolved_procedure_expression` and the reported header, so a checker following calls reaches bodies {#records.24}. The key includes `Exporter::own`: a compiler's own compile-time code (`#modify`) needs type records with real descriptors, which exports for a metaprogram don't have. Resolved headers carry the procedure's notes, including those after the body (`Compiler::proc_decl_notes`, copied to polymorph instances), and list `using` parameters in `parameter_usings` {#records.25}.
- A call to a polymorphic procedure resolves to the instance it made, not the generic procedure: sema records the instances each call span made (`ExportState::call_instances`, filled in `match_candidate`), and `Exporter::instance_called_at` picks the one belonging to the resolved procedure {#records.30}. The instance's header has no `POLYMORPHIC` flag, and its body is reported in a later TYPECHECKED message once lowered, exported in the scope of its bindings. A static `#if` there has `static_if_flags` `EVALUATED_AS_TRUE` when the condition held, and a static `if x == {` switch has `static_if_accepted_case`, so a checker can follow only the branch the compiler took (MetaThreadSafe does) {#records.31}. In a generic body the condition is unknown and neither is set.
- When a workspace runs out of sources, `step` lowers everything reachable (`Compiler::lower_reachable`, lenient: a failing body stays queued). If that reports new declarations or bodies (a body can declare more through `#insert,scope(...)`), the metaprogram gets another `TYPECHECKED_ALL_WE_CAN` and may add code {#records.27}. Only a round that reports nothing new proceeds to `finish_program` and code generation.
- `stdlib/Compiler/records.jai`: `record_struct(id, expected)` returns the struct the tag names (`RECORD_TYPES`, else the expected pointee type), zero-filled and filled member by member from the record: integers, enums, bools and floats by size, strings, pointers (recursively and memoised, so a record maps to one pointer forever {#records.9}), in-place structs, and arrays of those. `using` members and anonymous unions are filled from the same record. `record_of(pointer)` maps back. Every `Code_*` struct sets its own kind (`base.kind = .IDENT;`), so nodes a metaprogram makes with `New(Code_Ident)` behave like exported ones {#records.19}.
- Libraries like or_return, MetaThreadSafe and Jai-Shader-Transpiler read `Code_Procedure_Call.resolved_procedure_expression`, `Code_Ident.resolved_declaration` and `Code_Node.type` {#records.10}. Those need the compiler, which a `MetaOp` can't reach while the interpreter runs. So jaic traps and reruns:
- Value expressions get `type` by checking them in the code's scope without emitting (`Exporter::expr_type`). One that reads a local (`Exporter::reads_local`) gets none, since the code's scope does not have the local. Untyped literals report their default (`s64`, `float32`) {#records.13}.
- Type records carry `__address`, the real descriptor in this program's memory, so `type == type_info(T)` works {#records.11}.
- Prints the node tree with `Program_Print` and passes the text to `__jaic_parse_code`, which parses it (`build::parse_code_text`) into a new `Interp::codes` entry and records in `Interp::made_codes` whose scope it takes (`code_to_copy_scope_from`). The compiler adopts such codes (`Compiler::adopt_made_codes`) when it reads a `Code` back or adds one of its own, re-parsing the text as a registered source so diagnostics can point into it. Node edits the printer can't express are lost (see [Program_Print](../specs/stdlib/modules/program-print.md)). Names in the result resolve where the original code was written {#records.12}. A compile-time run that is repeated to serve a typed `compiler_get_nodes` replays the attempt before it: `Interp::run_codes` lists the codes the run made, in order, and the repeat's n-th `compiler_get_code` gets the n-th of them back (when its text and scope are the same) instead of a new code whose nodes it would ask for again. So `code_to_string(compiler_get_code(root))` in one expression finishes {#records.29}. Each call outside a repeat makes a code of its own, as each `#code` does.
- The edit is queued and applied at the workspace's next step (`Compiler::modify_procedure`): unchanged statements map back to their AST, `#code` roots are re-parsed from `__source`, edited ones from their text, inside a dummy procedure. The modified body is what runs {#records.18}. The `ProcLit` is replaced, and if the body was already lowered it is lowered again into the same function once the registry borrow is released (`relower_modified`).
