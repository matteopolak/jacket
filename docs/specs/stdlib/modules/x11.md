## Contracts and constraints

This module provides Xlib/X11 bindings and helpers for Linux desktop integration, including window/event and selection/file-dialog related declarations. Xlib resources are tied to a `Display` connection and must be released with matching Xlib calls; event structures and atoms are server/ABI-level values. Some bundled file-dialog routines are external `libsofd` bindings and require that dependency. The module is target-specific and does not hide X server errors or connection lifetime.

Clipboard data in `x_global_clipboard_buffer` is module-owned storage. The input selection handler serves UTF-8 text and advertises the supported target list; it advertises BMP image data only while `rgb_data` is present. Image data is encoded as BMP when a requester asks for that target. `x_release_clipboard_data()` releases the stored text and pixel buffers, clears their pointers and dimensions, and locks/unlocks the initialized global display while doing so. The global clipboard atoms and other X atoms are populated by the X11 initialization path after a display connection exists; callers must not treat their zero-initialized values as usable atoms before that setup. The selection protocol is asynchronous and depends on selection-request events being dispatched through the input handler. The module does not promise a synchronous system clipboard read/write API or a particular owner after another X client claims the selection.

`init_global_display()` returns immediately when `x_global_display` is already non-null. On first use it initializes X threading, opens the default display, interns the module's WM and clipboard atoms, the XDND atoms, `JXSelectionWindowProperty`, and the BMP image atom, attempts X input-method setup, creates the invisible cursor, and resets XDND state. The PNG/JPEG image atoms in the public inventory are not initialized by this procedure. It has no result or explicit failure return; a null display is not reported through its signature. It does not close the display or provide a matching reinitialization routine.

`enable_drag_and_drop(window, typelist)` treats each string as an X atom name. It replaces the target window's XDND type-list property with those atoms, replaces the module's stored user typelist, marks the target as XDND-aware at the supported protocol version, and also applies XDND awareness up its parent chain to the root. This helper requires successful global-display initialization first. `x_selection_notify_predicate` returns true only for a `SelectionNotify` event whose `requestor` equals the `Window` value pointed to by `arg`; it does not compare selection or target fields. The `arg` must point to a live `Window` value for the duration of the Xlib predicate call.
