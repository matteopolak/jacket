# Language server

## What it is

`crates/jai-language-server` is one JSON-RPC language server used by native editors (the `jailsp` binary, with `Content-Length` stdio framing) and the browser playground (the same `JsonSession` linked into `jai_wasm.wasm`).

Two layers:

- **Syntax** (always on): lexer/parser diagnostics (with quick fixes for their suggestions, such as an inserted `;`), semantic tokens, symbols, folding, selection ranges, format-string hover, `#load`/`#import` links. Built from the `jaic` lexer and parser; works while the text does not parse.
- **Semantic** (when the session has an `Environment`): everything needing the type checker: hover, completion, definition, references, rename, signature help, inlay hints, code actions, call hierarchy, code lenses, and [jailint](../tools/jailint.md) lints with quick fixes. Open documents are compiled with `jaic` and the compiler's editor facts are queried.

Not supported: formatting (use `jaifmt --stdin` as an external formatter), type errors in a polymorphic procedure nobody instantiates (sketches cover hover only), unopened files in workspace diagnostics, bare-name uses of `using`'d fields in references/rename.

## How it works

### Documents

Configuration files keep separate saved snapshots: changes apply on `textDocument/didSave`, not while typing. See [saved configuration](saved-configuration.md). Generic lenses aggregate real instances across workspace entry programs; see [polymorph reporting](polymorph-reporting.md).

`Session` holds versioned open documents. Each version is lexed and parsed once (`analysis.rs`; the symbol tree in `analysis/symbols.rs`) into declaration rows; `Analysis` keeps the token stream (`syntax_tokens`) so features never lex the text again. Positions are UTF-16. `position::LineIndex::byte` is the one place a protocol position becomes a byte offset, for requests and edits alike, and it never fails: a line past the last names the end of the document, a character past the end of its line names the line's end, and a character inside a surrogate pair names the start of that character (LSP 3.17). Only a reversed edit range is rejected. Each document keeps a `LineIndex` (`jaic::source`); `Session::change` updates it per edit with `LineIndex::update`, which rescans only from the line holding the edit, and a test checks it against a full rebuild over random edits. A stale version or invalid edit keeps the previous text. If a version does not parse, completion falls back to the last version that did.

Facts that come straight from syntax are the compiler's, not re-derived here: `jaic::parser::ide_facts` gives top-level items with their visibility and `#if` nesting (`top_level`), each procedure with its notes (`procedures`, for `@PrintLike`), a header's type parameters (`type_parameters`: baked parameters and `$T`) the call around a position with the active argument (`call_at`, for named-argument completion), the cursor's context (`cursor_context`) and declaration name spans (`decl_name_spans`, `inferred_name_spans`). `analysis.rs`, `exports.rs` and `named_arguments.rs` read these; extend `ide_facts` rather than matching tokens in the server. Holes of `@Interpolates` literals ([inline holes](../language/interpolates.md)) come from the compile's recorded literals plus the compiler's scanner, in `interpolation.rs`.

Half-typed text is compiled as it stands: the editor lexer and parser recover at line and grammar boundaries and keep every byte offset, so nothing is blanked or patched first. What the cursor is in (a string and the `#import`/`#load` it names, a comment, a `.` member access with its receiver chain, a declaration name) comes from `ide_facts::cursor_context`, built on the lexer; completion, path completion and inlay hints use it instead of scanning bytes. An inferred `.Member` (no receiver) compiles the text once with a placeholder name after the dot (`Session::complete_member_at`). Every semantic feature goes through `Session::checked`, so hover, hints and tokens of one version share one compile.

### Semantic analysis (`semantic.rs`)

Compiles on demand and caches by source text:

1. Open documents overlay the file system (`OverlayFs`; disk plus repo stdlib natively, the bundled `VirtualFs` in the browser).
2. The root is the open document that `#load`s the requested one, else the project entry (`jacket.toml` `[project] entry`, or an inferred `build.jai`/`first.jai`/`main.jai`/`src/main.jai`).
3. `compiler.ed.record(IdeFacts)` starts recording. Sema records what each identifier names, scopes, expansions and calls. Every hook is a no-op while the `Editor` is idle (a batch compile).
4. `ide_check_all` lowers every non-polymorphic body, not only what `main` reaches, and keeps each declaration's error separately (so several errors per file show). It also evaluates the field defaults of structs no value is made of, for their facts only: compilation never evaluates them, so their errors are dropped.
5. `ide_sketch_polymorphs` checks each uninstantiated polymorphic procedure and unexpanded macro, and each polymorphic struct with no instance, once with stand-in types so hover and completion work inside them. The sketch is then discarded; jailint ignores its facts.
6. Compile-time code runs in `SandboxHost` with a block budget, so a looping `#run` traps instead of hanging and never writes to protocol stdout. A call to a foreign procedure the sandbox does not provide (`mkdtemp`, a library's own symbols) is unknown, not wrong: `Editor::refuse_unavailable` records the `#run` like an untrusted refusal, the statement is salvaged, and `semantic::compile::known` drops the error, since a build runs it for real (tests: `tests/sandbox_unavailable.rs`). The sandbox stays on in trusted workspaces because analysis re-runs compile-time code on half-typed text.

Code in an `#if OS == ...` branch the target skipped is checked by compiling for the other targets until one takes it, always in `OTHER_TARGETS` order: code several targets check (the `else` of an `#if OS == .MACOS`) is then described the same way whatever was asked before.

**Build metaprograms.** For a project built by a metaprogram (`first.jai` calling `add_build_file`), the metaprogram is run and each workspace compiler becomes a `Program` in `Analysis::others`; `Analysis::focus(path)` picks the one that compiled a file. Afterwards `release_build_state` and `release_lowered_code` free metaprogram state and lowered IR, since nothing runs again.

**Build facts.** Project discovery (which program a file is in, which module folders it has) follows what the metaprogram *did*. `jaic::build::WorkspaceObserver::source_added` reports each `add_build_file`/`add_build_string`; `semantic::compile` turns them, plus the `import_path` the workspace ended up with, into `BuildFacts` (canonical keys, see [file identity](file-identity.md)), so computed paths (`tprint` + `#filepath`, variables, loops) are exact. `Cache::recorded` keeps the last run that finished without errors per build file; a failed or budget-exhausted run never replaces it. `Session::sync_builds` hands them to `Index::builds`; `Index::closure` and `modules::find_import_dirs` prefer them over the static scan (`add_build_file` literals, `FileScan::import_paths`), which still applies before the first run. When no entry's loads reach a file, `Session::run_unrecorded_builds` runs the `[project] entry` files once; `Index::probed` keys that on a hash of the metaprogram, its loads and `jacket.toml`, so editing `main.jai` does not rerun `build.jai`. Folders a past run added are not handed back to its next run, so deleting an `import_path` line takes effect. Runs happen in `SandboxHost` (writes stay in memory, no processes or network) under `BLOCK_BUDGET`, the same budget as any other metaprogram run. Tests: `tests/build_facts.rs`.

### Cache and memory

A large program compile is hundreds of MiB, so `semantic::Cache` keeps `CACHED` (2) compiles, plus up to `ALTERNATES` for other targets. It keeps one compile per program, preferring the newest one that checked and read the most source, so a half-typed edit does not evict the last good compile. Compiles of at most `SMALL_COST` bytes of source (a file that imports little) are not counted against `CACHED`, up to `SMALL_KEPT` of them, so a second open file that imports nothing is not compiled again after every edit of the main program. Rules to keep:

- `jailsp` installs `large_alloc::LargeBlocksToOs` (blocks of 128 KiB or more via `mmap`) and trims after each compile; this is the crate's only `unsafe`.
- Answers that grow with the file (`documentSymbol`, semantic tokens) are written straight to text (`Reply::Raw` in `protocol.rs`), not built as `serde_json::Value`.
- Per-request work must be cached on `Document` or by position index (`IdeFacts::refs_at`, `member_use_at`), never rescan the file. Drop references with `IdeFacts::truncate_refs`.
- Compiles share parse trees through `jaic::parser::ParseReuse`, one per thread for every session on it (`semantic/cache.rs`, `shared_parses`). It also keeps each file's decoded text and line index (`ParseReuse::source`, taken only for identical bytes), so a kept tree's text is the very `Rc<str>` it was parsed from. Trees must never be mutated after parsing.
- Push diagnostics are debounced in `jailsp`: the wait is a quarter of the last publication's time, between 15 and 200 ms (`DIAGNOSTICS_DEBOUNCE` in `main.rs`); edits that arrive during a compile are read together afterwards, so a short wait is enough for small programs. This way a completion request does not wait behind a compile. Clients advertising `textDocument.diagnostic` get pull diagnostics instead and no pushes.
- Finding a document's program must not cost a walk of the tree. `Index::graphs` keeps the direct loaders of every file under a folder (`ProjectFs::loader_graph`, built by `project::build_loader_graph`); `Index::graph_epoch` moves on only when a scan sees `#load` paths that differ from the file's last scan (`Index::note_loads`), a file is created or deleted, or the set of open and walked files changes. An edit that leaves the `#load`s alone (almost every keystroke) reuses the graph; before this, each keystroke in a stdlib file read every file of the stdlib again.
- Module lists (`Index::stdlib`, `module_dirs`) are per module: a module remembers the files it was read from, and a changed file only makes those modules stale (`ModuleCache::stale`), which `Sources::refreshed` reads again on the next ask. Do not drop a whole list on a file change.
- The stdlib's module list is shared by the sessions of a process (`module_index.rs`, `SharedStdlib`, up to four kept). While it is read, `Sources` records every path it asks about with its `FileSystem::stamp` and the options asked for. Another session takes it only while every stamp and those options are unchanged and none of its open documents is one of those paths or lies in one of those folders; otherwise it reads its own. A list read through an open document or a build's facts is never shared. A new way for `Sources` to reach the file system must call `note` too, or a change there is missed.
- Lints run after every compile, so rules must not read or lex the files around the edited one again. `unused_import` keeps what it counted in a file by hash of its text (`FILES`) and `unused_parameter` keeps the definitions of a file by modification time and size (`DEFS`), both thread-local with a size cap. A rule that reads another file should cache the same way, or a lint of a large module costs more than the compile.
- Workspace symbols read the listed files by their keys (`Sources::scan_keyed`, `Sources::open`); asking `canonical_key` or `open_file_uri` for each listed path is a `realpath` per file per request.
- Completion does not compile while a word is typed: it reuses a compile whose text matches up to the cursor expression (`Cache::compiled_before`).
- A compile is keyed on every open buffer, but typing in a file a program never loaded must not recompile it. `semantic::OverlayFs` records each path a compile reads or tests and each folder it tests (`Reads`); compile-time file reads (`#run` reading a file) go through the same file system, so they count. `Cache::lookup` reuses a kept compile of the same root when every buffer that changed, appeared or went away is outside its `Reads`, including folders: a new unsaved buffer at a path the compile looked for is a change. Queries after the compile add to the same `Reads`. Tests: `tests/compile_reuse.rs`.
- Work beside the editor's (polymorph summaries) compiles through `Cache::cached` (no compile, no change to the recently-used order) or `Cache::compile_detached`, which keeps the most recently used compile and the newest one that checked its root, and does not keep its own.
- `JsonSession::background_work` does one piece of deferred work (today: stale polymorph summaries, see [polymorph reporting](polymorph-reporting.md)). `jailsp` calls it only while no input waits, after the auto-import warm-up, so a request is never queued behind more than the one compile in progress (a compile cannot be interrupted). When the queue drains and a summary changed, clients with `workspace.codeLens.refreshSupport` get `workspace/codeLens/refresh`.

### Features worth knowing

- **Completion**: `ide_scope_at` finds the scope; `ide_visible` lists names, `ide_members` lists members after `a.b.`. The typed word is cut out so the probe text is stable across keystrokes. An inferred `.` completes the expected enum's members. Items carry a `textEdit` covering the whole word. `#asm` blocks have their own completion, hover and signature help (`asm.rs`, instruction data from `jaic::sema::asm_catalog`; see [asm](asm.md)).
- **Ranking by expected type** (`Session::fitting_names`): where a type is expected (call and named arguments, the right side of `=` or a typed declaration, `return`, `if`/`while` conditions) the names whose value converts to it come first. The word being typed is replaced by a placeholder `.NAME`, and the compiler records the type its context expected for it (`inferred_expected`, the same fact inferred-member completion uses). `Compiler::ide_fitting_names` keeps the names whose `IdeName::ty` passes `implicit_cost`, the checker's own conversion rule, so no conversion table lives in the server. Fitting names get a `0` `sortText` prefix and the others `1`, before the usual rank (`rank`), so the order inside each group is unchanged; named-argument items (`!`) and auto-imports (`~`) keep their place, nothing is hidden, and with no expected type `sortText` is as before. To cover another position, make the checker pass `expected` to an inferred member there; to change what fits, change `implicit_cost`. `IdeName::ty` is set only for values whose type is already resolved (unresolved declarations never fit).
- **Call and keyword snippets** (`call_snippets.rs`): when the client advertises `completionItem.snippetSupport`, a procedure item becomes `name($0)` / `name()$0` (`CompletionItem::call` is the `IdeCall` the checker or `exports.rs` recorded: whether every overload is parameterless, and the leading required parameter names for `fillArguments`) with the `editor.action.triggerParameterHints` command when the cursor lands inside. `call_snippets::site` reads the lexer tokens around the word to decide where parentheses do not belong (next token `(` or a declaration colon, `#procedure_of_call`, `type_of(`/`size_of(`/`type_info(`/`cast(`, prefix `*`, `::` and global `:=` initialisers, type positions after `:` `->` `$`). Statement keywords `if`/`for`/`while` expand only when they start a statement with nothing after them on the line; `case` only directly inside the braces of `... == {`. The default is `addParentheses` rather than rust-analyzer's `fill_arguments`: Jai parameters often have defaults, are variadic or are polymorphic, so placeholders would mostly be deleted again, and signature help shows the parameters anyway. Items from the syntactic fallback (no type checker) and `#asm` templates are not affected.
- **Postfix completion** (`call_snippets.rs`): after `value.` the snippets `if`, `while`, `for`, `return` (only where a statement starts), `not` (`!value`) and `ref` (`*value`) replace the receiver and the typed word (`textEdit` from the receiver's start; `filterText` is `receiver.label` so the client still matches what was typed). Offered only for a receiver the checker says is a value (a module or type receiver gets none; a call or index is a value) and only to snippet clients.
- **Typed hints** (`typed_hints` in `features/actions.rs`): inferred declaration types, argument names, `#run` values, and the implicit `it`/`it_index` of a `for` that names neither (`it: string, it_index: s64` before the iterated expression; the compiler records them in `Ide::implicit_loop_names`, `ide_implicit_loop_names`).
- **Closing-brace hints** (`closing_hints.rs`): `Session::inlay_hints` adds `// name` after the `}` of a procedure, struct or enum at least `closingBraceMinLines` long, from the document symbols' ranges (no type checker needed), next to `typed_hints`.
- **Struct literal fields** (`struct_literal.rs`): where a field name goes in `Foo.{ | }`, `.{ | }` or `x: Foo = { | }` (right after `.{`, a `{` that directly follows `=`, or a `,` of the literal, no positional value before it; a `{` anywhere else opens a block) the unassigned fields of the literal's type are offered with their types as detail, ranked first in declaration order (`!` plus the field's index as `sortText`), with the first one left `preselect`ed so the client selects it whatever it remembers, and inserted as `name = `. The tokens decide the position and which fields the literal names already; the type comes from the compiler: the word is replaced by a placeholder field `__jailsp_field = 0`, and `check_struct_literal` records the struct type under that name's span in `inferred_expected` (`Compiler::ide_literal_fields` lists its fields, `using` ones and polymorphic instances included). A call nothing accepts, which is the case while the literal is incomplete, records the parameter type for the field names of a `.{...}` argument in `ide_note_unmatched_inferred`. Its shared `inferred_argument_types` query treats that argument as a hole, infers polymorphic bindings from other arguments and ranks viable candidates normally. Variadic arguments use the element type. The query cannot execute compile-time code or lower procedure bodies; unresolved bindings remain unknown. As the first entry the normal expression items remain after the fields (it may be a positional value); once a field is named only fields are offered. Values after `=` and after a positional value are ordinary expression completion, expected-type ranking included.
- **Member paths and generated code**: a receiver's members are the union over every receiver the checker recorded at that span (`IdeFacts::receiver_sets`: a module, a type and a value can all be live at once, as in a generic header or an instance and its stand-in), so `g.W` and `Box(int).T` list a struct's constants and parameters, `using` members and `using,only` aliases come through `t.height`, `context.Alias.` and `#Context .X` resolve through the context struct, enums list `loose` and borrowed `using` names, and `#filepath.` completes as a string. Definitions in text an `#insert` generated, or a program-added string, land on the `#insert` site (`ide_surface_span`, `SourceState::insert_sites`) since that text is not a file. In editor mode a body that fails is retried once the rest of the program has been lowered (`drain_bodies_lenient`, `provisional_errors`), so a name a later `#insert,scope` declares is not reported as unknown; the earlier error is withdrawn when the retry succeeds. A file is a module only when it really writes `#module_parameters` (`writes_module_parameters` lexes; a comment does not count), and workspaces kept for `get_type_table` are handed to the observer when the metaprogram ends (`jaic::build::hand_over_kept`).
- **Auto-import**: names from stdlib modules, project modules and unloaded project files are offered with an `additionalTextEdits` `#import`/`#load`. `auto_import.rs` builds items (module discovery in `auto_import/module_index.rs`, which program a file belongs to in `auto_import/programs.rs`), `exports.rs` lists a file's declarations from `ide_facts::top_level` (every name of a multi-name declaration; files with errors are scanned as far as they parse), `project.rs` finds the program. Stdlib files are offered only through their modules, even when the workspace holds the stdlib; a file inside a module folder sees that folder's files by `#load` and never `#import`s its own module. Modules are ordered by `jaic::sema::ModuleRanking` (shared with the compiler's "add `#import`" help): modules the project already imports first (most imports first), then stdlib modules by how many other stdlib modules import them (counted when the module index is built), `Extensions/` last. Max 50 items; needs 2+ characters. Disable with `completion.autoImport: false`.
- **Module roots**: a root that is a module file (`Name/module.jai` at any depth under an import path, `Name.jai` directly in one, or any root declaring `#module_parameters`) is compiled through a synthetic program (`.jailsp-module-root.jai`, only in the overlay) that `#import`s it with default parameters, so `#module_parameters` is legal and hovers/diagnostics still map to the real files. Files the module `#load`s reach it through the loader chain. See `module_entry` in `semantic/compile.rs`; `jailint` does the same via `Root::Module`.
- **Loaded fragments**: a file that nothing in its program reaches but another file `#load`s (`stdlib/internal/input/keymap-text.jai`, loaded by `Keymap/module.jai`) is analysed as part of that loader, so it sees the loader's declarations and imports. `auto_import.rs` `loader_chain` calls `jaic::project::enclosing_program` (see [project structure](project.md)) over the cached token scans of every `.jai` file under the enclosing stdlib tree (or the workspace/jacket.toml folder) and walks up to a file nothing loads. Several loaders: `module.jai` first, then the shallowest path, then by name. Diagnostics shown are the fragment's own file; module roots and `#import`ed files are their own program. Nothing is compiled to pick the owner, and the folder walk and scans are cached with the auto-import index.
- **Hover**: contextual `using,only`, `using,except`, and `using,map` modifiers are described from lexer tokens, including while the filter is incomplete. These names remain ordinary identifiers elsewhere. Extend `features/hovers.rs` for syntax-only descriptions; no semantic environment or configuration is needed. Imported selector hover/definition still uses the compiler's filter facts. Other hovers are built as `hover::Block`s and written as Markdown or plain text depending on the client's `contentFormat`. Shows types, overloads, macro expansions, `#run` values and output, `#if` results, format-string arguments, and memory layout (size, align, padding, field offsets from the compiler's own layout). Doc comments appear under signatures ([doc comments](doc-comments.md)). A value (local, constant or member) of struct type is shown with its fields, one per line under the `///` docs of the field's declaration (`ide_value_type` in `ide/describe.rs`); when the type's name was cut short ([type names](diagnostics.md#type-names)) the polymorphic struct's bare name heads the list. Docs of a declaration in generated text (`#insert`, macros) are read from the text the compiler kept, not from the `#insert` site that go to definition shows (`ide_hover_decls` uses `ide_definition_in_sources`).
- **Definition/references/rename**: from recorded references. Struct fields and enum members are `(use span, declaration span)` pairs in `IdeFacts::member_uses`. Rename refuses declarations outside project files.
- **Diagnostic help and quick fixes**: `Analysis::check_findings` (`semantic/queries.rs`) turns each compile error and warning into a `CheckFinding`: the message plus its unlocated notes (`note:`), listed suggestions and `help` lines (`help:`) as one text, and located notes as `relatedInformation` (`model::RelatedInformation`). The first 50 errors also get their render-time help (`Compiler::with_name_suggestion`: similar names, the modules that declare a name), kept with the compile. `suggestion_fixes.rs` turns every suggestion of every error and warning near the cursor (or named by the client, code `check`) into a `quickfix` whose edits are the suggestion's; `isPreferred` only for `Applicability::MachineApplicable`. An `Edit::Import` is placed by `suggestion_fixes::insertion` (after the last import) and dropped when the file has the import. To give a diagnostic an editor fix, attach a `Suggestion` in the compiler (see [diagnostics](diagnostics.md#suggestions)); the server needs no change. Tests: `tests/suggestion_actions.rs`, `tests/features/quick_fixes.rs`.
- **Lints** (`lints.rs`): run on documents that parse, from real text. The `[lint]` table of `jacket.toml` (nearest above, or an open copy sent via `didOpen`) sets levels. Quick fixes carry the rule in `data.rule`; `source.fixAll.jailint` applies all machine-applicable fixes.
- **Unreachable code**: `Session::unreachable_diagnostics` publishes a `Hint` diagnostic (code `unreachable`, `DiagnosticTag.Unnecessary`, so editors fade it and draw no squiggle) for each range `Analysis::unreachable` returns. The facts come from the checker, see [unreachable code](sema.md#unreachable-code-reachabilityrs-intervalrs). Not in files the analysis does not record.
- **Expansions**: `jai.showExpansion`, `jai/expansion` and `jai-expansion:` URIs show what an `#insert`, `#run` or macro produced; `jai/source` returns text for any URI the client has not opened.
- **Signature help**: `open_call` scans back to the unmatched `(`; recorded call facts are used when present, else the callee is looked up in scope.
- **Semantic tokens**: the legend is append-only; a token's wire type is `SemanticTokenKind as u32`, so `SemanticTokenKind::ALL` lists the kinds in declaration order and `name` gives each legend name. Here-strings tagged with a language (`#string WGSL`) get no token so the editor can highlight them; `jaic::lexer::LANGUAGE_TAGS` must match `EMBEDDED_LANGUAGES` in `editors/vscode/scripts/build-grammar.ts`, which checks it through `editors/lexicon.json`.

### Project settings

`[project]` in the `jacket.toml` at the project root (see [jacket](../tools/jacket.md)):

```toml
[project]
entry = ["first.jai", "src/main.jai"]   # entries (what jaic is given)
import_path = ["vendor/modules"]        # extra module folders, like -import_dir
```

Configs are read through the open buffers over the disk and cached per directory by the hash of their text (`config.rs`). A config that does not parse is treated as empty and reported once with `window/showMessage`. A config with no `[project]` entries (a lint-only one) does not make its folder a project. Without it, entries are inferred from the workspace folder. Module search order is `jaic::project::import_paths` ([project](project.md#import-paths)): `modules/` next to the root file, `import_path`, then the extras the editor adds, then the stdlib. The extras are an editor leniency the command line does not have: `modules/` of each folder above the root file up to the project base, and string literals in entry files that mention `import_path` (`modules.rs`; nothing is run), replaced by what the metaprogram recorded once it has run. They go in with `jaic::project::add_import_dirs`; folders that do not exist are dropped. A module file not reached by any `#load` is checked in the context of the entry that imports it (`Sources::closure_with_modules`).

### Protocol

`JsonSession::handle_json` parses a message (`incoming`) and hands it to `handle_request` or `handle_notification`. Method names are mapped once, in `Request::METHODS` and `Notification::METHODS`; each method is a match arm or a small `JsonSession` method returning `Result<_, Failure>`, where `Failure` pairs an `ErrorCode` (the JSON-RPC/LSP codes) with a message. Request ids are `RequestId` (`protocol/request_id.rs`): a string, an integer, or a float with a zero fraction such as `1.0`, which a response echoes in the form it came in; `1` and `1.0` are the same id for `$/cancelRequest`, and any other number or type is `Invalid request id`. `$/cancelRequest` and `exit` skip the lifecycle check; other methods before `initialize` get `ServerNotInitialized`, after `shutdown` `InvalidRequest`. Each handler runs under `catch_unwind` (`guarded`); a panic becomes an `InternalError`, caches are reset and open documents survive (not on `panic = "abort"` builds such as wasm). Non-standard requests: `jai/source`, `jai/expansion`. Documents use absolute `file:///` URIs (the browser uses `file:///jai-script/<name>`). The wasm bridge (`crates/jai-wasm/src/language_server.rs`) keeps the session in a `thread_local` because compiler state uses `Rc`; the worker message is `{type: "lsp", id, message}`.

## How to change it

- **Check differently in an editor**: the checker never tests `ed.is_live()` to decide what to do. It asks a policy method on `Editor` (`ide/editor.rs`), which gives the build's answer when not recording: `stmt_failed` (go on past a failed statement, declare or salvage its names), `recovers_exprs`/`sketching` (stand-in values), `keep_going`/`keep_going_once` (declaration and import errors), `allows_parse_ahead`, `checks_every_body`, `trusts_reachability`, `counts_scope_changes`, and `Compiler::failure_reusable` for retried bodies. Add a named method for a new decision, so the batch behaviour stays readable at the call site.
- **Record more facts**: add a sema hook calling an `ide_*` method guarded by `self.ed.is_live()`, or an event method on `Editor` (`ide/editor.rs`) when sema only reports something happened; keep it cheap. Sema never reads or writes `IdeFacts` itself, and analyses only an editor needs live in `ide/`: polymorph sketches (`ide/sketch.rs`), expression values and branch narrowing (`ide/values.rs`), procedures that never return (`ide/never_returns.rs`). Name facts go in `ide/facts.rs`, call and metaprogramming facts in `ide/meta.rs` (module `jaic::ide`). Extend `ide_hover`/`ide_entity_hover` to show them.
- **New hover content**: add a `hover::Block` kind with cases in `HoverText::plain` and `HoverText::markdown`.
- **New block scope**: call `ide_scope_span`, or completion inside it sees only the enclosing scope.
- **New expansion kind**: add an `IdeExpansionKind`, record it where the compiler evaluates it, handle it in `kind_name`, `describe`, `expansion` and `code_actions` (`features.rs`).
- **Print-family names** are the list `format::PRINT_FAMILY` (diagnostics publish without compiling); keep format semantics in step with `stdlib/Basic/Print.jai` and `jailint::format_string`.
- **Token legend**: append a `SemanticTokenKind` variant, to `ALL` and to `name` (`model.rs`); modifiers are `TOKEN_MODIFIERS` in `lib.rs`. Never reorder. `protocol.rs` tests check the order.
- **New request or notification**: add a variant and its method name to `Request::METHODS` or `Notification::METHODS`, then an arm in `JsonSession::request`/`notification`. Commands are `ServerCommand::NAMES`.
- **Environment**: native `main.rs` `native_environment`, browser `language_server.rs` `environment`; keep both in step with how `jaic` and the playground compile.
- **Lint rules** live in `crates/jailint`; the server picks them up unchanged.
- **Typed results** live in `model.rs`; extend them and the wire mapping in `protocol.rs` together.

Tests are in `crates/jai-language-server/tests/` (`semantic.rs`, `features.rs`, `auto_import.rs`, `links.rs`, `protocol.rs`, `resilience.rs`, plus refactor and hierarchy tests) and in `crates/jai-wasm/src/language_server.rs`. `node tools/browser/check_scripting_wasm.mjs <jai_wasm.wasm>` runs the same against the real wasm module.

## Configuration

```sh
cargo run -p jai-language-server --bin jailsp
cargo test -p jai-language-server
cargo build --release -p jai-wasm --target wasm32-unknown-unknown
node tools/browser/check_scripting_wasm.mjs target/wasm32-unknown-unknown/release/jai_wasm.wasm
```

- `JAIC_STDLIB` overrides the native stdlib directory. `JAIC_PRELUDE` selects a prelude file relative to that directory, or an absolute path; see [prelude selection](prelude-selection.md). The prelude supplies built-in types and context before the main file is checked.
- `jacket.toml`: nearest above the document.
- `initializationOptions` / `workspace/didChangeConfiguration` (`jai` section): `completion.autoImport` (default `true`), `completion.callSnippets` (`addParentheses` default, `fillArguments`, `none`), `inlayHints.closingBraceMinLines` (default 25, 0 is off), `trusted` (default `true`; `false` runs no compile-time code, see [workspace trust](../tools/workspace-trust.md)). `jailsp --untrusted` starts untrusted; the `jai/setTrusted` notification switches at runtime.
- Constants: `semantic.rs` (`BLOCK_BUDGET`, `CACHED`, `SMALL_COST`, `SMALL_KEPT`, `ALTERNATES`, `PARSES_KEPT`), `auto_import.rs` (`MAX_ITEMS`, `MIN_PREFIX`; the project tree walk limits are `jaic::project::MAX_TREE_FILES` and `MAX_TREE_DEPTH`), `ide/meta.rs` (`MAX_EXPANSIONS`, `MAX_CALLS`, `MAX_VARIANTS`, `MAX_TEXT`), `features.rs` (`HINT_CHARS`).
- `Limits` are safety caps (512 documents, 32 MiB per document, 64 MiB per message); `Limits::browser()` is smaller. A document over a cap is not opened and the client gets a `window/showMessage`.
- Benchmark: `PYTHONPATH=tools python3 tools/bench/main.py lsp` ([benchmarks](../tools/benchmarks.md)).

## Dependencies

`jaic` (lexer, parser, sema with `IdeFacts`, `SandboxHost`), `jailint`, `serde`/`serde_json`. In the browser it is reached through `engine.lsp(message)` ([playground](../browser/playground.md)). Protocol: LSP 3.17 over JSON-RPC 2.0.

- When `jailsp` has no input waiting it reads the auto-import module indexes (stdlib and project modules; `Session::warm_auto_import`), which cost a few hundred ms once, so the first completion of a name is not slow.
