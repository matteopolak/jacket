# Doc comments

Comments directly above a declaration are its documentation, written in Markdown. The language server shows them in hover, completion and signature help and resolves `[name]` links in them; `jacket doc` builds the API site from them and `jacket test` runs their examples. Comments do not affect program execution; compiler tooling retains their documentation facts.

## Convention

A declaration's docs are the run of `//` lines (`///` and `//!` work too) directly above it with no blank line, or a `/* */` block ending directly above it. One space after the marker is removed; the rest is Markdown. A line of only `-----`, `=====` or four or more `/` ends the run.

```jai
// Scales a [Point] by `factor`, starting from [`Mode.IDLE`].
//
// - factor: how much to grow
scale :: (p: Point, factor: int) -> Point { ... }

x: int; // trailing comments document fields, members and parameters
```

- Fields, enum members and parameters may have a trailing comment or lines above them. A trailing comment counts only after a whole declaration with no `{`, so `f :: () { // note` doesn't document `f`.
- A parameter's doc is a comment above it or in the header, else a list item in the procedure's docs starting with its name (`- name: text`).
- A line that is exactly `@experimental` marks a module (in the comment opening `module.jai`) or an item as experimental. `jaic -doc_model` strips it and reports `experimental: true`; hover shows *Experimental*. Use it instead of a warning sentence.
- Links are rustdoc-style: `[print]`, ``[`print`]``, `[Basic.print]`, `[Point.x]`, `[Mode.IDLE]`, `[text](print)`. An unresolved link stays plain text (jailint's `broken_doc_link` reports it), as do `a[i]`, `[0]`, URLs and code.
- A constant that only renames another (`hello :: Impl.hello;`) with no comment of its own shows the target's docs. Document the target only.

## How it works

- `crates/jaic-syntax/src/docs.rs` (shared with jailint) works from lexer tokens, no parse. A comment belongs to the declaration whose first token follows it. Links come from `pulldown-cmark`.
- `doc_view.rs` is the glue for the language server. Hover reads docs from the compiler's copy of the file, so stdlib works like open documents. Links resolve with `Compiler::ide_resolve_path` from the scope of the documented declaration and are rewritten to `file://` URLs.
- Completion lists up to `EAGER_DOCS` (24) items with docs inline; longer ones defer to `completionItem/resolve`.
- Alias forwarding is `docs::docs_site` in `crates/jaic-syntax/src/docs/forward.rs`, the only place that decides it. `jaic -doc_comments` resolves from the library's files and `jacket test` skips alias records so an example runs once.
- `jaic -doc_model <dir>` records ordinary type names and alias-chain declaration identities through `doc_comments/refs.rs` and `model_resolution.rs`. Directive identifiers are syntax: `*#Context` does not refer to a user declaration named `Context`, while `*Context` and `*Other.Context` retain their normal references. Aliases to the compiler-provided `#Context` and `#jaic_type` expressions are classified as types using their AST directive kind. Language-guide destinations are configured separately by `jacket doc`.
- Highlighting: `editors/vscode/syntaxes/jai-doc-comments.tmLanguage.json` injects Markdown scopes into comments. `jai.tmLanguage.json` (generated by `scripts/build-grammar.ts`) wraps runs of comment lines in `meta.comment-run.jai` so fences can span lines.

## How to change it

- Convention (what counts as a doc, parameter items, links): `docs.rs`. Alias forwarding: `crates/jaic-syntax/src/docs/forward.rs`. Tests: `doc_comments.rs` and the language server's `tests/doc_comments.rs`.
- Type-reference collection: `crates/jaic-syntax/src/doc_comments/refs.rs` and `model_resolution.rs`, with identity/collision regressions in `model_tests.rs`.
- What a link can name: `ide_resolve_path` in `crates/jaic/src/ide/definition.rs`. Link colour: `target_kind` in `doc_view.rs`.
- Markdown styling: the regexes in the injection grammar, plus a case in `editors/vscode/test/grammar/doc-comments.jai` (`pnpm run test:grammar`).
- Gotchas: extraction starts at the name's offset, so a literal on the next line takes docs above the name's line. Block comments count only when they end directly above the declaration and start their line. Completion answers from the last compile, so `Analysis::shift_to` must move declaration offsets below an edit.

See [language server](language-server.md).

## Configuration

There is no separate type-reference setting. `JAIC_STDLIB` and `-import_dir` select the library search roots used by `jaic -doc_model`; `[[doc.page]]` entries in `jacket.toml` publish Markdown guides independently of declaration references.

## Dependencies

The parser and shared documentation resolver in `jaic-syntax`, `pulldown-cmark` for Markdown links, and the language server and Jacket site renderer as consumers.

## Compiler model wire contract

`jaic -doc_model DIR` emits `schema: "jai-doc-model"` and `schemaVersion: 1`. It records compiler facts independently of the website and requires no Node. Jacket strictly deserializes the whole object: unknown fields/versions/kinds, missing required values, malformed reference tuples and invalid dependency hashes are errors. A reference is exactly `[writtenName, declarationFile, declarationLine, private]`; declaration identity comes from the compiler rather than a display-name match.

The model includes a dependency list of compiler-read files and their lowercase SHA-256 content digests. A same-size edit must invalidate the recorded content identity. Site export adds effective configuration/source provenance; the hashes do not imply an implemented incremental cache.

Written type declarations retain every conditional definition with its kind, documentation, scope, platform/guard facts, source byte bounds and compiler-read content digest. Exact code-token spellings and declared-name positions are separate from authored whitespace. Each grouped member has its own name-token identity; nested declarations cannot borrow an outer member's fragment. Parser-declared identifiers, notes and literals are not reference uses: in `Collision: Collision`, only the type use receives a resolved link. Private-page dependency closure includes references from every conditional definition.

Jacket verifies private source identities and batches those declarations through the existing `jaifmt` documentation profile. It rejects token spelling/order changes and maps compiler identities onto formatter-produced UTF-8 offsets. The permanent site contract carries formatted text and typed semantic anchors, not source spacing or statement-layout instructions. Astro displays that text and applies responsive soft wrapping without another Jai syntax formatter. Ordinary Markdown paragraphs and code examples remain independent content.

Defaults are limited to fields the producer omits when empty, such as empty reference/`also` lists and false binding/private flags. Struct, union, enum and enum-flags records without token facts are errors. The compiler no longer serializes the raw source-layout `declaration` field, and Jacket rejects it as an unknown wire field. Source locations and source links remain available separately. Update `doc_comments/model.rs`, Jacket's `doc/model/wire.rs` and malformed-input regressions together; reject `"binding": "false"` rather than interpreting it as a boolean. No environment variable relaxes admission.

See [documentation export](doc-site-export.md) for the two versioned contracts, generation workflow and consumer boundary.
