# Compiler intrinsics

## What it is

Procedures declared with `#intrinsic` are not given Jai bodies; the compiler lowers a call to a fixed IR operation chosen by the procedure's name. The memory and atomic ones are declared in `stdlib/prelude/module.jai`.

## How it works

`stdlib/prelude/module.jai` declares:

```jai
memset :: (dest: *void, value: u8, count: s64) #intrinsic;
memcpy :: (dest: *void, source: *void, count: s64) #intrinsic;
memcmp :: (a: *void, b: *void, count: s64) -> s16 #must #intrinsic;
compare_and_swap :: (pointer: *$T, old: T, new: T) -> (success: bool, old_value: T) #intrinsic;
```

`emit_intrinsic` in `sema/calls.rs` maps the name to an `ir::Intrinsic` (`memcpy`, `memset`, `memcmp`, `compare_and_swap`, `debug_break`, `sqrt`, `sin`, `cos`, `floor`, `ceil`, `round`, `trunc`, `abs`/`fabs`, `rdtsc`/`get_cpu_cycle_count`, `pause`/`mm_pause`). Any other name is a located error:

```
error: unknown intrinsic 'frob'
```

For `compare_and_swap` the operand width (1, 2, 4 or 8 bytes) is taken from the value type and passed to the IR as an extra constant. Verified output:

```jai
x: s64 = 5;
ok, old := compare_and_swap(*x, 5, 9);   // true 5, x == 9
ok, old  = compare_and_swap(*x, 5, 1);   // false 9, x stays 9
```

`memcpy`/`memset`/`memcmp` behave as expected (`memcmp` returns the sign of the first differing byte; `memcmp(a, b, n) > 0` after zeroing `b` is true). `#intrinsic` procedures take no implicit context (`has_context` in `sema/procs.rs`).

Taking an intrinsic's address or storing it in a variable goes through `lower_intrinsic_wrapper` (`sema/procs.rs`), which generates a small function around the IR op. Only `memcpy`, `memset`, `memcmp` and `debug_break` have real wrappers there; any other name becomes a `Trap`, so do not rely on pointers to the math intrinsics.

Other IR operations that user code never names directly are generated by the compiler itself: `BoundsCheck` (array indexing, `expr.rs`), `IsCompileTime` (`#compile_time`), and the bit operations used by `#asm` lowering (`sema/asm.rs`, see [simd and asm](simd-asm.md)).

Pools (`stdlib/Pool.jai`, `stdlib/Flat_Pool.jai`) are ordinary Jai code, not intrinsics.

## How to change it

Add an `ir::Intrinsic` variant in `crates/jaic/src/ir.rs`, implement it in the interpreter (`crates/jaic/src/interp/`) and in `crates/jaic-llvm`, add the name to the `match` in `emit_intrinsic` (and `lower_intrinsic_wrapper` if it must be usable as a value), then declare it with `#intrinsic` in `stdlib/prelude/module.jai` or a stdlib module. Keep the declared signature in sync: `emit_intrinsic` does not type-check beyond the declaration.

## Configuration

None.

## Dependencies

`stdlib/prelude/module.jai`, `sema/calls.rs`, `sema/procs.rs`, `ir.rs`, the interpreter and LLVM backend.
