# VS Code extension

## What it is

`editors/vscode/` is the Visual Studio Code extension (ID `matteopolak.jacket`, AGPL-3.0-or-later): a TextMate grammar, language configuration and snippets, a client for [`jailsp`](../compiler/language-server.md) (which also carries [jailint](jailint.md) findings and fixes), [`jaifmt`](jaifmt.md) as the document formatter, *Run/Build/Check File* commands, and a downloader for the compiler release named in its checksum manifest. The extension version and compiler version are independent, so a checksum repin can ship without a compiler bump. It ships as a `.vsix` on GitHub releases and is published to the Marketplace and Open VSX.

## How it works

```
src/extension.ts         activation, LanguageClient, restart, jacket.toml sync, formatter
src/discovery.ts         finding jailsp, jaic, jaifmt (pure; unit-tested)
src/toolchain.ts         archive per platform, checksums, download, versioned install (pure)
src/toolchainManager.ts  prompts, progress, remembered answers
src/jaifmt.ts            ignore query (`jaifmt --is-ignored`), minimal edit, jaifmt --stdin
src/commands.ts          Run/Build/Check File as tasks
src/expansion.ts         jai.showExpansion / jai.showPolymorphs, jai-expansion: documents
scripts/build-grammar.ts writes syntaxes/jai.tmLanguage.json
scripts/build.ts schemas writes schemas/jailint.schema.json (from jailint's RULES) and jaifmt.schema.json
```

- **Highlighting.** The grammar is generated from the keyword and directive lists at the top of `build-grammar.ts` and written from the compiler's lexer and parser, not another editor's files. It is the fast baseline; `jailsp` semantic tokens refine it. Doc comments get Markdown styling from a hand-written injection grammar (`syntaxes/jai-doc-comments.tmLanguage.json`, tests in `test/grammar/doc-comments.jai`).
- **Embedded languages.** A here-string whose terminator names a language (`#string WGSL ... WGSL`; also GLSL, HLSL, MSL, SQL, JSON, HTML, CSS, XML, Lua, JS/TS, Python, shell, C/C++/ObjC, Rust, YAML, TOML, Markdown, JAI; matched ignoring case) is highlighted as that language. Each language is one rule in front of the plain here-string rule: a `begin` lookahead captures the tag, and a `begin`/`while` rule continues while lines do not start with the tag, so an unclosed construct cannot swallow the file. `package.json`'s `embeddedLanguages` (generated) maps the scopes to VS Code language IDs for comments and brackets. If a language's grammar is not installed, the rule is dropped and the string stays plain. `jailsp` skips known tags in semantic tokens (`jaic::lexer::here_string_tag` and `LANGUAGE_TAGS`).
- **Migration notice.** Once per machine, when the first workspace folder has a legacy config file and no `jacket.toml`, `offerToMigrate` shows a notice with a button that runs `jacket config migrate` in a terminal (`jai.migrationNoticeShown` in the global state). The `jacket.toml` JSON schema (`schemas/jacket.schema.json`) is generated by `scripts/build.ts schemas` with the others.
- **Language client.** Starts `jailsp` over stdio for `file:` documents. `JAIC_STDLIB` comes from `jai.stdlib.path` and `JAIC_PRELUDE` from `jai.stdlib.prelude` ([prelude selection](../compiler/prelude-selection.md)); entry files, module folders and lint levels from the nearest `jacket.toml` ([project settings](../compiler/language-server.md#project-settings), [jacket](jacket.md); the legacy `jai.toml` and `jailint.toml` still work). Settings go as `initializationOptions` and `workspace/didChangeConfiguration`; configuration sends and server replacements share a lifecycle queue. Tool paths and prelude settings restart the server; live settings update the running client without restarting. Keep configuration forwarding in the extension’s handler rather than also enabling the language client’s automatic forwarding, which can send through a stopping client. The file watcher covers Jai sources and all four supported TOML files. The extension forwards `didOpen/didChange/didSave/didClose` for those settings files itself (`SETTINGS_FILES`); edits apply on save.
- **Binary discovery.** `jailsp`: `jai.server.path`, `PATH`, next to `jaic`, downloaded toolchain. `jaic`: `jai.compiler.path`, `PATH`, download. `jaifmt`: `jai.formatter.path`, `PATH`, next to `jaic`/`jailsp`, download. A configured path that does not exist is an error naming the setting, never a silent fallback.
- **Toolchain download.** With nothing found, `jai.toolchain.autoDownload` (`prompt`/`always`/`never`) decides. The archive name comes from `RELEASE_ASSETS` (`${platform}-${arch}` to `jacket-<platform>.tar.gz`, `.zip` on Windows). It is checked against `toolchain-manifest.json` (compiler version and SHA-256 of each archive, written at packaging time by `tools/ci/toolchain_manifest.py`; development builds fall back to the release's own manifest; see [releases](releases.md#toolchain-manifest)), unpacked with system `tar` into staging, then renamed to `<globalStorage>/toolchain/<version>/`. A cached folder whose recorded hash differs from the current pin is replaced; older versions are deleted only after the new one is installed.
- **Formatting.** `jailsp` has no `textDocument/formatting`, so the extension runs `jaifmt --stdin` in the document's folder, first skipping files the config's `ignore` list covers (asked of `jaifmt --is-ignored <file>`; `--stdin` does not apply the list). It returns one edit covering the changed span; on failure it leaves the text alone and shows jaifmt's message.
- **Commands.** *Run/Build/Check File* save and run `jaic <file> [-interp|-check] <jai.run.arguments>` as a task. Refactorings, call hierarchy and expand selection are plain `jailsp` capabilities with no extension code. `source.fixAll.jailint` works with `editor.codeActionsOnSave`.

## How to change it

```sh
cd editors/vscode
corepack enable && pnpm install
pnpm run build           # grammar, schemas, dist/extension.cjs
pnpm run lint            # oxlint, tsc, generated files up to date
pnpm test                # unit and grammar tests
JAILSP=../../target/debug/jailsp [JAIFMT=...] pnpm run test:e2e
pnpm run package         # jacket-vscode-<version>.vsix
```

To try a change by hand, `just vscode-try [FOLDER]` (from the repository root) builds the tools and the extension and opens VS Code with only this extension, in a throwaway profile that points at the built binaries. Without `FOLDER` it opens a temporary copy of `examples/`.

- **Grammar:** edit `build-grammar.ts`, rebuild, add assertions to `test/grammar/*.jai` (vscode-tmgrammar-test: `^` under tested columns). `scripts/tokenize-corpus.ts` tokenizes `examples/` and `stdlib/` and fails on a token left open; run it on the upstream corpus after big changes.
- **New here-string language:** add the tags to `LANGUAGE_TAGS` in `crates/jaic/src/lexer/here.rs`, regenerate `editors/lexicon.json` (below) and add the language to `EMBEDDED_LANGUAGES` in `build-grammar.ts` (the build fails while they differ), and to the playground's table if supported. Avoid common generic terminators.
- **New jailint rule:** nothing; the schema regenerates and lint fails while stale. **New jaifmt.toml key:** `scripts/build.ts` (`schemas`). **New release platform:** one row in `RELEASE_ASSETS` (a unit test compares it with the `release.yml` matrix).
- **Icons:** `pnpm run icons` (`scripts/build.ts icon`) regenerates SVG/PNG icons from the playground glyph; lint fails when stale. **Screenshots** for the README: `pnpm run screenshots` on macOS (`test/screenshots/`).
- **Dependencies:** pnpm is pinned by `packageManager`. Every npm package must be at least 14 days old ([development](development.md#dependency-policy)); `pnpm-workspace.yaml` sets `minimumReleaseAge` and `scripts/check-dependency-age.ts` rejects non-registry lockfile entries and ages pnpm itself in CI. `@types/vscode` must not be newer than `engines.vscode`.

Gotchas:

- Tooling is Rolldown (`rolldown.config.ts`): `dist/extension.cjs` for the extension; `--environment TESTS` transpiles `src/` and `test/` to `out/**/*.cjs` for tests. Scripts run as `node scripts/x.ts` (erasable TypeScript only).
- `vsce package` needs `--no-dependencies` (everything is bundled) and a `LICENSE` beside `package.json` (the package script copies it).
- Integration tests use a short `--user-data-dir` (macOS socket path limit); `VSCODE_EXECUTABLE` uses an installed VS Code.
- A store version cannot be replaced, so a checksum repin needs a new editor version (`editor_version` input of `release.yml`).
- The extension was `matteopolak.jai` (to 0.4.1) then `matteopolak.jai-toolchain`; `activate` checks `OLD_EXTENSION_IDS` and, if one is installed, registers nothing and offers to uninstall it (duplicate command registration would throw). Drop an ID once few installs remain. The Marketplace requires a globally unique name, which is why it is `jacket`.

## Configuration

| Setting | Default | Effect |
| --- | --- | --- |
| `jai.server.path`, `jai.compiler.path`, `jai.formatter.path` | `""` | tool locations (accept `~`, `${env:NAME}`) |
| `jai.stdlib.path` | `""` | `JAIC_STDLIB` for jailsp and jaic |
| `jai.stdlib.prelude` | `""` | `JAIC_PRELUDE` for jailsp and jaic; expands `~` |
| `jai.toolchain.autoDownload` | `prompt` | `prompt`, `always`, `never` |
| `jai.completion.autoImport` | `true` | complete names from unimported modules and add the import |
| `jai.completion.callSnippets` | `addParentheses` | what accepting a procedure inserts: `addParentheses`, `fillArguments`, `none` |
| `jai.inlayHints.closingBraceMinLines` | `25` | name the closing brace of procedures, structs and enums this many lines long (`0` is off) |
| `jai.run.arguments` | `[]` | extra arguments for the commands |

In an untrusted workspace `server.path`, `compiler.path`, `formatter.path`, `stdlib.path`, `toolchain.autoDownload` and `run.arguments` are ignored when set by the workspace (`restrictedConfigurations`), jailsp is started with `trusted: false` (no `#run`, build metaprograms or computed `#insert`), Run/Build/Check File refuse, and granting trust restarts the client. See [workspace trust](workspace-trust.md).
| `jai.trace.server` | `off` | `messages`/`verbose` log LSP traffic |

Test environment: `JAILSP`, `JAIFMT`, `VSCODE_EXECUTABLE`.

CI (`vscode-extension` job in `ci.yml`): dependency ages, `pnpm run lint`, `pnpm test`, integration tests under `xvfb-run` with a stand-in formatter (`test/e2e/fake-jaifmt.ts`), and the `.vsix` as an artifact. In `release.yml` the `vscode` job packages the VSIX, attaches it to the release and `SHA256SUMS`, and publishes the same package to both stores with `--skip-duplicate` using secrets `VSCE_PAT` (Azure DevOps token, scope Marketplace Manage, publisher `matteopolak`) and `OVSX_PAT` (Open VSX token, Eclipse publisher agreement signed); without them the steps skip. Manual publish: `gh release download <tag> -p 'jacket-vscode-*.vsix'`, then `pnpm exec vsce publish --packagePath ...` and `pnpm exec ovsx publish ... -p "$OVSX_PAT"`. Deprecating old IDs: Open VSX needs a PR to `open-vsx/publish-extensions` (`extension-control/extensions.json`, `disallowInstall` with replacement `matteopolak.jacket`); on the Marketplace use *Manage Publishers, Deprecate*.

## Dependencies

VS Code 1.91+, `vscode-languageclient` (bundled), system `tar`, and the toolchain (`jailsp`, `jaic`, `jaifmt`). Development: pnpm, TypeScript, Rolldown, oxlint, `@vscode/test-electron`, `vscode-tmgrammar-test`, `@vscode/vsce`, `ovsx`, `@resvg/resvg-js`. Internal: the `jailsp` protocol (`crates/jai-language-server/src/protocol.rs`), jailint's rule table, jaifmt's `--stdin` contract and release archive names.


## Trying the development toolchain

`just vscode-try` builds `jacket`, `jaic`, `jailsp`, `jailint`, the formatter and this extension, then opens a throwaway VS Code profile. Its editor paths and new integrated terminals select the same local build; `jacket run +Foo` therefore uses the development compiler instead of an installed release. The profile also sets `JAIC_STDLIB` to this checkout’s stdlib. Existing terminals keep their old environment, so open a new terminal after switching profiles.

The setup lives in `tools/dev/dev.py` (`vscode_settings`, `cmd_vscode_try`). Keep the terminal PATH, editor paths and build package list aligned when adding a tool. `CARGO_TARGET_DIR` or Cargo’s configured target directory chooses the build location; `--debug` selects the debug profile. Dependencies are Cargo, pnpm, the VS Code CLI and the local toolchain sources. Tests in `tools/dev/test_vscode_try.py` check that the generated profile and build agree.

Development extension bundles are already unminified and include `dist/extension.cjs.map`; only `PRODUCTION` builds minify. Use these source maps with the extension-host debugger to inspect TypeScript sources. Startup failures log the full error stack to the Jai output channel; the language-client channel records protocol and process errors. Saving settings may stop the old server successfully as part of replacement, which is distinct from a startup failure.

The settings-replacement regression checks configuration-send errors specifically. A busy server may exceed the graceful shutdown budget and log `Stopping server timed out` without showing a popup; that warning must remain visible and is separate from sending through a retired client.
