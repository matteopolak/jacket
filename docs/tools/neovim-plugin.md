# Neovim plugin

`editors/nvim/` is the Neovim 0.11+ plugin for Jai: an `lsp/jailsp.lua` config for [`jailsp`](../compiler/language-server.md), `jaifmt` formatting, a Vim syntax file, a `:Jai` command and a toolchain downloader. It mirrors the [VS Code extension](vscode-extension.md). Install steps and settings are in [`editors/nvim/README.md`](../../editors/nvim/README.md).

```lua
require('jai').setup({
  stdlib = { path = '/path/to/stdlib', prelude = 'Base.jai' },  -- optional
})
```

## How it works

- `lsp/jailsp.lua` sets `cmd` to a function, so the binary is looked up when a Jai buffer needs it. `plugin/jai.lua` adds `:Jai` and calls `vim.lsp.enable('jailsp')` unless `lsp.enable = false`. `ftdetect/` and `ftplugin/` handle `*.jai` and format on save; `syntax/jai.vim` is the fallback under semantic tokens.
- `lua/jai/`: `config.lua` (defaults < `vim.g.jai` < `setup()`), `toolchain.lua` (find tools: setting, `PATH`, next to `jaic`, `stdpath('data')/jai/<version>`), `install.lua` (archive per platform, SHA-256 check, `curl` download, `tar` unpack; `TOOLS` lists the five executables every archive must hold, kept in step with the VS Code extension), `format.lua` (`jaifmt --stdin`, `jaifmt --is-ignored`), `commands.lua`, `health.lua`, `version.lua` (generated by `tools/generators/generate_version_files.py`) and `toolchain-manifest.json` (stamped in by the release; see [toolchain manifest](releases.md#toolchain-manifest)).
- `:Jai` subcommands: `fix` (asks for `source.fixAll.jailint`), `lint` (runs `jailint` into the quickfix list), `expand`, `polymorphs`, `costs`, and run/build/check/install/restart.

## How to change it

- **A setting:** add it to the defaults and `jai.Config` annotation in `config.lua` and the README table. If `jailsp` should receive it, add it to `config.server_settings()` and the server side (`JsonSession::configure` in `protocol.rs`).
- **Compile-time limits** (`compile_time.*`) go to `jailsp` like the VS Code `jai.compileTime.*` settings; `jai/compileTimeLimit` notices are shown by `lua/jai/limits.lua` ([limits](../compiler/compile-time-limits.md)).
- **Trust:** `trusted` (default `true`) is sent to `jailsp` and gates `:Jai run/build/check` ([workspace trust](workspace-trust.md)).
- **A `:Jai` subcommand:** `subcommands` in `commands.lua`. **A platform:** a row in `install.asset_for` and the VS Code `RELEASE_ASSETS`. **The archive layout** changes here, in the install scripts and in VS Code together.
- Syntax words in `syntax/jai.vim` copy `editors/vscode/scripts/build-grammar.ts`; nothing checks them against each other.
- Gotchas: `vim.lsp.enable()` doesn't attach to buffers already open, so `restart` re-triggers `FileType`; use `vim.uv`, never `vim.loop`.

Tests are [mini.test](https://github.com/echasnovski/mini.test) specs in `editors/nvim/tests/*_spec.lua` (helpers in `tests/harness.lua`). `PYTHONPATH=tools python3 tools/dev/fetch_mini_test.py` fetches mini.test at the commit pinned as `mini_test_commit` in `.github/pins.json`.

```sh
just nvim-test            # builds a debug jailsp, runs everything
just nvim-test --unit     # without the end-to-end spec (what `just check` runs)
```

`JAILSP` names the server for the end-to-end spec.

## Publishing

Plugin managers need a repo whose root is the plugin, so the `neovim` job in `release.yml` copies `editors/nvim/` to `matteopolak/jacket.nvim` (`main`) and tags it with the editor version. Existing tags never move: an identical rerun is fine, different content under a tag fails and needs a new `editor_version`. The job needs the `NVIM_MIRROR_DEPLOY_KEY` secret (a write deploy key on the mirror repo) and skips without it.

## Dependencies

Neovim 0.11+, `curl` and `tar` for `:Jai install`, `sha256sum`/`shasum`/`openssl` on Unix, and the toolchain binaries. No Lua dependencies.
